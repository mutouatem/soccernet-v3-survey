1. 一页结论

  • 这批文献里没有人在做"换视角 + 时序"的球员 re-ID。 102 篇中，以视角不变匹配为核心贡献的只有 SoccerNet-v3 原论文（数据集）本身；以 re-ID 为核心的 6 篇（#30、#31、#33、#34、#95、#103）里 4 篇是单视角或跨模态；在 v3 跨视角数据上做方法研究的只有 #103 一篇，而它是单帧的，对视角差异没有任何显式设计；唯一显式处理跨相机差异的方法论文 #34 经深读与审稿核对不可作为参照。
  • SoccerNet-v3 的跨视角 re-ID 标注基本被绕开了。 172,622 条直播↔回放对应，报告过成绩的只有三处：两届挑战赛报告（#104：2022 首届冠军 Inspur mAP 91.68 / Rank-1 89.41；#56：2023 冠军 CLIP-ReIdent 93.26 / 91.26；都是 challenge set 上的多模型集成）和一篇方法论文（#103 RFES-ReID：单模型、test split，mAP 86.7 / Rank-1 84.1，方法上没有针对视角的设计）；标定方向凡用到 v3 数据的 12 篇全部只用其场地线（另 6 篇仅背景引用），#30 明确拒绝用它，#82 主动剔除回放画面。这是一个标注已就绪、方法几乎空着的 benchmark。
  • 身份识别的实际进展都发生在单机位。 Game State Reconstruction 从基线 GS-HOTA 22.26（test）/ 23.36（challenge）做到 61.48（#28，test）与 63.81–64.1（#23、#82，challenge）。能说明"瓶颈不在 re-ID 特征"的证据是 #20 的 oracle 消融（ReID 换成真值仅到 87.42，球衣号才是最大瓶颈）和 #28 的身份模型替换实验（换掉 OCR 组合后 18.11 → 60.13），冠军系统 #23 本身没有消融；长时程单相机身份（#95 LTPI）CSIS 0.716，残余错误主要是同队混淆（t-SNE 定性）。
  • "序列有用"有硬证据，"时序模型有用"证据不足。 tracklet 从 1 帧到 7 帧 Rank-1 +31 点（#31）；关键帧过滤约 +38 点（#80）；但 #33、#32、#88 三处非受控对比显示简单均值/投票是很强的基线，而 #56 号码识别冠军用的恰是 tracklet transformer。能下的结论只有一条：任何时序模块都必须与同骨干、同数据的 mean-pooling 对照。
  • 视角不变的线索已经各自验证过，只是没在跨视角设定下组合。 球衣号（#32/#35，tracklet 级 test 87–88%）、球场坐标（经标定后视角无关）、球队/角色、阵容/时间约束（#95 MisID 0.208 → 0.174）。属性识别器（CLIP 或 VLM）在单机位上已验证有效（#28：换掉 OCR 组合后 18.11 → 60.13 / 61.48），但视角无关性未被验证——#29 的号码识别跨项目掉了 15 个点。
  • 外观表征对视角变化没有任何显式设计。 被复用最多的 PRTreID（#30）只处理"部位缺失"，不处理同一部位跨视角的外观差异；2D 表征的视角敏感性可以让性能从 50 跌到 5（#86）。
  • 几何基础设施基本就绪，但有 22% 的洞。 #59 已为 v3 的 4,051 张多视角帧算出可靠标定；非主机位/回放帧的标定完整率停在 77–78%（#2/#8）——恰恰是跨视角最需要的那部分。
  • 最直接的切入点：把 v3 的单帧对应升级为序列级跨视角基准（#79 + #47 + #18 的组合），用几何一致性做候选剪枝与难负样本挖掘（#59），在 PRTreID 上加视角对齐损失（#31 的 MSRL 改写），并沿用 #95 的弃权感知长时程协议。详见第 5 节。

3. 换视角 re-ID 与时序建模：语料中的最新进展

3.1 问题界定：语料里的"换视角 re-ID"长什么样

先说清楚一件事：这批引用 SoccerNet-v3 的文献里，"跨视角球员重识别"作为一个被正面攻关的研究问题，几乎不存在。102 篇里 crossview 评分为 3（核心贡献是视角不变匹配）的只有 SoccerNet-v3 原论文本身；reid 评分为 3 的 6 篇（#30、#31、#33、#34、#95、#103）里，有 4 篇是单视角或跨模态设定，只有 #103 在 v3 的跨视角数据上做实验，而它的方法对视角差异没有任何设计。真正"跨视角"这三个字在语料里以四种彼此很不一样的形态出现：

形态 A：转播直播帧 ↔ 回放帧的单帧对应（SoccerNet-v3 本身）。 这是语料中唯一带人工身份标注的跨视角 re-ID 数据。#79 的构造方式决定了它的性质：每个 replay clip 只选 1 帧（在 5 fps 抽帧序列里挑"最能展示同一时刻"的那帧，与 live 帧最大偏移 100 ms），得到 21,222 张 replay 帧 ↔ 12,764 张 live 帧；跨视角球员对应共 172,622 条，球衣号 106,592 个。身份只在一个 folder（1 张 live 帧 + 它的所有 replay 帧）内一致，不跨动作、不跨整场；身份键实际是 (team ID, jersey number) 二元组，无号码者用共享的 generic literal ID，只出现一次且无号码的球员没有 ID。全部是单帧，没有 tracklet。审稿核对特别指出：原文从未列举 replay 机位类型（近景/球门后/反向是推测），也没有按机位报告标注难度。在这份数据上报告过成绩的，语料里只有两届挑战赛报告（#104、#56）和一篇方法论文（#103），见 3.3(a)。

形态 B：固定多相机体育场。 #86 SGA-INTERACT（4 台相机、3x3 篮球）用 SOLIDER Re-ID + OCSORT 单视角跟踪，再靠跨视角 Re-ID 多数投票 + 三角化确定全局身份，但发布的只有 3D 骨架、无 RGB；#55 DeepSport 的 raw-instants 是同步多相机全景图 + 完整内外参，但没有跨相机身份标签；#34 在自采的 12 相机休闲运动数据上做无监督跨相机聚类，数据不公开。

形态 C：单相机长时程身份保持。 #18 SoccerNet-Tracking 的标注协议是"目标离画后回归仍保同一 ID"；#95 LTPI 把它推到整场 101 分钟、3,087 个 visibility fragment 的 track 级身份分配。这两者没有视角变化，但有"时间"这一维。

形态 D：单个移动转播机位的 Game State Reconstruction。 #20/#23/#28/#29 在一个不断 pan/zoom 的转播镜头内做跟踪 + 身份属性 + 球场坐标投影。视角在时间上连续变化，但没有第二个相机。

与传统行人 re-ID（Market-1501 / MARS）相比，这个领域的难点是结构性的：同队球员穿完全相同的球衣（#95 的 t-SNE 定性显示误识别主要发生在队内簇重叠处，论文未报告分队错误统计；#104 与 #56 的组织者自述 v3 ReID 的困难是"同队外观高度相似、每个身份样本极少、分辨率差异大"）；姿态剧烈、分辨率低（#95 中球员平均高只有 54 px，号码基本不可读）；视角切换是突然的、非连续的（直播远景 → 回放近景）。可用的额外线索也很明确：球衣号（稀疏但强）、球场坐标（经标定后视角不变）、时序一致性、球队/角色等语义属性。

3.2 锚点：SoccerNet-v3 的 re-ID 标注到底能支持什么

把 #79 的深读结论压缩成对研究者有用的几条（均经审稿核对）：

  • 它是"困难跨视角单帧配对"的现成来源：query/gallery 可按 folder 内 live 帧 vs replay 帧组织，不需要视频（png 帧 + json 即可通过 SoccerNet pip 包下载）。
  • 它不能直接支撑常规 re-ID 的大 gallery，也不能做长时序身份：ID 不跨 folder，同一球员在不同动作里的 ID 互不关联，即使球衣号相同也未被声明为全局身份。任何在 v3 上做的 re-ID 评测都应说明这是 folder 内匹配。
  • ID 覆盖依赖球衣号可见性（深读推断，原文未讨论）：无号码但在多张图中出现的球员仍得到共享的 generic ID，被完全剔除的只是"只出现一次且无号码"者；深读认为这仍会系统性剔除一部分最难的负样本，使评测偏向"号码可见"的情形。
  • 同帧带 20 类场地线 + 6 类球门部件点标注，可先做标定（#59 已经用 PnLCalib 为其中 4,051 帧算出了可靠的 {K, R, t}），把各视角球员投影到统一球场坐标。这是纯外观 re-ID 在同色球衣场景下缺失的信号。
  • 时序扩展路径存在但需自建：每帧带 SoccerNet-v2 的动作时间戳与比赛引用，理论上可回原视频（需 NDA）抽取 live 与 replay 两侧的 tracklet；审稿人提醒原文未说明能否凭元数据精确定位到 replay 帧在原视频中的位置。
  • 论文本身无任何 baseline 数字，评测协议留给 SoccerNet Challenge；跨视角检索的成绩要看 #104（2022 首届）、#56（2023）和方法论文 #103。协议上目前能确认的只有 #103 转述 challenge 网站的几条：身份标签只在 action 内有效；评测时每个 query 只与同一 action 的 gallery 样本比较；train 共 248,234 个样本，test split 为 query 11,777 / gallery 34,989。
  • 坐标系绑定主机位（审稿核对补充）：Fig. 2 假设"主机位在图的底部、靠近中线"，20 类线的 top/bottom/left/right、球门的左右、team ID 的左右都以此为参照；在回放机位上做几何或语义约束时必须先换算。
  • 这是经过筛选的子集：SoccerNet-v2 有 32,932 条 replay clip（500 场），v3 只有 21,222 张 replay 帧（400 场）——只标注了 400 场、unshown 动作被删、标注员反馈后又移除了一批图像，因此"真正可对应"的样本存在选择偏差。
  • 球、主裁、线、球门的跨视角对应需用户自行建立，数据中不显式存储（原文的依据是"given their uniqueness"）。
  • 时间元数据的含义未逐项界定：replay 帧附带 start / end / localization time，但原文没有说明三者的精确定义，也没说能否凭它们定位到原视频中的 replay 帧位置——切入点 1 依赖这一点。

3.3 方法谱系

(a) 跨视角基准上的实际成绩：两届挑战赛加一篇方法论文

在 SoccerNet-v3 跨视角 re-ID 任务上报告过数字的，语料里一共三处：#104 SoccerNet 2022 Challenges（首届）、#56 SoccerNet 2023 Challenges，以及方法论文 #103。两届的任务定义相同：在某一时刻的某个 action 内，跨多个相机视角检索同一球员/裁判；数据 340,993 个球员缩略图（400 场、6 大联赛），分为 train / valid / test / challenge 四份，排行榜按 challenge set 的 mAP 排名。

2022 首届（#104）：13 队 123 次提交。冠军 Inspur mAP 91.68 / Rank-1 89.41，其后 MGSoccer 91.48 / 89.21、MTVACV 90.11 / 87.04、gunners 89.47 / 86.42、MIG 89.44 / 86.11，前 9 名都在 86 以上，而官方 baseline（sn-reid）只有 59.11 / 48.41。各队的方法摘要合起来是一份很具体的配方清单：

  • 应对"每个身份样本极少"：删掉图像过少的身份（Inspur 删少于 3 张的，#103 删少于 4 张的）+ focal loss。
  • 大骨干或自监督预训练：Inspur 用 ResNeSt269 + Arc/Cos-Softmax；MGSoccer（MGN 式 CNN + TransReID 式 ViT）与 MIG 用 LUPerson 上的自监督预训练；MTVACV 进一步用 Catastrophic Forgetting Score 从 LUPerson 里筛出与 SoccerNet 域接近的图像做 DINO 预训练，并加了"可见性与重要性感知"的身体部件特征——与 3.3(b) 的 PRTreID 思路同源。
  • 围绕 action 结构设计采样：MGSoccer 让每个 action 取等量身份；ReBatch 把同一 action 的图像放进同一 batch，以得到最难的 triplet；MIG 反过来按"A 个 action × I 个身份 × K 张图"随机取大量 action，并点明了原因——同一球员在不同 action 里 ID 不同，同场比赛的多个 action 放进一个 batch 会产生假负样本。
  • 推理侧：多分辨率/多模型的距离矩阵融合（Inspur、MTVACV、MIG 的 5 模型）；ReBatch 的排名互斥后处理（若所有模型都把某张 gallery 图排在某个 query 的第一位，就在其它 query 的排名里把它后移）——这其实是在利用"同一 action 内每张 gallery 图只属于一个人"的分配结构。
  • 在 challenge set 上做推理期无监督域自适应：Inspur 自述"加入测试阶段数据"，组织者把它列为各队共性经验的第 (vi) 条。

2023（#56）：冠军 UniBw Munich 的 CLIP-ReIdent：3 个 CLIP 视觉编码器（OpenCLIP + OpenAI）集成，InfoNCE 对比微调，训练时按 action 采样（同一时刻的多视角一起进 batch），推理按 action 做 re-ranking。challenge set mAP 93.26 / Rank-1 91.26，test set mAP 93.51；表中的 baseline 91.68 / 89.41 经 #104 核实就是 2022 年冠军 Inspur 的成绩。参赛从 13 队 123 次提交降到 5 队 28 次，两年只涨了 1.6 个 mAP 点。

唯一的方法论文（#103 RFES-ReID，Scientific Reports 2024）：Swin-T 骨干，每个 stage 前插入一个 Regional Feature Extraction Block（把 token 还原成特征图 → 3×3 空洞卷积 + GELU → 残差相加 → 展平回 token），损失为交叉熵 + triplet + focal，检索时加 k-reciprocal 重排序。只在 train split 上训练，在 test split（query 11,777 / gallery 34,989，逐 action 检索）上评测，单模型：Swin-T 基线 Rank-1 75.3 / mAP 80.2 → +RFEB 79.6 / 81.4 → +融合损失 81.8 / 85.0 → +重排序 84.1 / 86.7。它的 Table 4 是语料里唯一一张 v3 ReID 的多骨干对照表：

三点解读。第一，challenge 的 91–93 与方法论文的 85–87 不是一回事。前者是多模型集成、大规模自监督预训练、外加在 challenge set 上做推理期自适应的结果；后者是单模型、不看测试数据。中间这 6–7 个 mAP 点主要来自工程手段，不能读成"问题已经解决"。做方法研究应以 #103 的 Table 4（以及同量级的 Sports Re-ID、TransReID-SSL）为对照，而不是排行榜。

第二，任务是单帧、逐 action、候选池很小的检索，更像"配对"而非"检索"，与 Market-1501 上的 mAP 不可比。协议细节现在清楚了一部分：身份只在 action 内有效，query 只与同一 action 的 gallery 比较，test 规模为 11,777 / 34,989（#103 转述 challenge 网站）。按 #79 的 12,764 个 action 与 340,993 张缩略图粗算，平均每个 action 约 27 张缩略图；再按 test 的 query : gallery ≈ 1 : 3 折算，每个 query 面对的候选只有 20 张左右（我的估算，非官方数字）。是否只用直播帧作 query、回放帧作 gallery，每个 action 有几个身份，mAP 怎样跨 action 汇总，材料仍然没写，需要去读 sn-reid 仓库。

第三，同一个 CLIP-ReIdent 在 DeepSportradar 篮球 ReID（同相机、同视角、跨时刻）上 mAP 0.98（#57），但那是一个组织者自认已饱和的小挑战集，扩大到 query 618 / gallery 9,505 后官方基线跌到 61.1——两组数字不同运动、不同候选池，不能用来估计"视角代价"；视角代价在语料内没有任何测量，#103 与两届挑战赛也都只报告总体数字，没有按视角差（远景直播 vs 近景回放）分桶。

#56 还有两项与本题直接相关的结果。跟踪冠军 Kalisteo 的 TrackMerger v2（HOTA 75.61，基线 42.38）把无歧义 tracklet 作为身份单位，用 triplet 微调 MGN re-ID 再按 re-ID 向量合并 tracklet——这是 3.3(d) 所说"目标域轨迹自适应"的公开挑战赛版本。它的第一版出现在 #104：2022 年的跟踪任务给定真值检测框、只评关联，TrackMerger HOTA 93.64 / AssA 88.06（基线 70.89）；两届设定不同，不能连成一条进步曲线。球衣号识别冠军 ZZPM（92.85%）与 J3/J5 方案用的是 tracklet token transformer / video transformer，这与后文"简单聚合往往足够"的观察方向相反，3.3(d) 会正面处理。

(b) 外观表征与多任务身份学习：PRTreID 系

#30 Multi-task Learning for Joint Re-identification, Team Affiliation, and Role Classification（PRTreID，MMSports 2023）是语料中被后续工作复用最多的球员 re-ID 表征——#20 GSR 基线、#82 SoccerFactory、#95 LTPI 基线都直接拿它做 backbone。结构：HRNet-W32，BPBReID 式 body-part attention（K=5 部位 + 背景，OpenPifPaf 伪标签监督），每部位一个 embedding 加二值可见性分数 v_k。三项目标：re-ID 用 GiLt loss（margin 0.3）；team affiliation 用 foreground embedding 上的 triplet（margin 0.05、λ=0.1，仅对 player 角色计算，推理时逐视频 K=2 的 K-means）；role 用 focal loss。匹配距离（Eq. 3）只对 query 与 gallery 双方都可见的部位求欧氏距离再平均。

数字（自建 SoccerNet-Tracking 派生集，query 1146 ids / 3432 张，gallery 13719 张）：mAP 72.59 / Rank-1 89.57，对比 BPBReID 71.43 / 89.31、PCB 63.61 / 80.39、BoT 62.63 / 80.24。team 检索 mAP 92.89，逐视频 K-means 分队准确率 91.87% → 95.6%。跟踪（PRT-Track，oracle 检测）HOTA 90.77，最接近的对手 CBIoU 89.20，StrongSORT++ 84.08。

审稿核对给出的警示：(1) 多任务对 re-ID 的增益很小（+1.2 mAP），且 ReID+Role 单独的 mAP（72.78）高于全模型（72.59），论文正文"联合模型在所有任务上优于所有部分模型"的说法与自己的表格矛盾；(2) 只用 team 或 role 目标训练会让 re-ID 崩溃（mAP 约 10–12、Rank-1 4.28），身份损失必须是主导项；(3) 全部数据来自单一主摄像机（作者明确放弃了 SoccerNet-ReID 的跨相机数据，理由：无视频、无跨动作标注）；Table 1 的 "# cameras" = 57/49/49 与片段数吻合、很可能就是视频片段数，但论文从未定义该列——审稿人把这一点以及"身份按 clip 独立、query–gallery 同 clip"都列为推断，并指出若 camera = clip，标准 re-ID 的同相机过滤会剔除全部正样本，即 re-ID 评测协议本身没有交代清楚；(4) batch sampler 描述的数字自相矛盾（11 id × 4 张 ≠ 32）；(5) TrackMerge 的形式化不完整（对角线 +∞ 的完美匹配，未给合并阈值与拒绝机制）；(6) Eq. 7 的 tracklet 部位可见性取"历史任一检测可见即为 1"的并集，长序列中会保留陈旧的部位特征；(7) Table 3 与 Table 4 的 PRT-Track HOTA（90.77 vs 90.84）不一致；(8) 作者自认最接近的工作是 Zhang et al. 2020 的多相机多球员跟踪（共享 backbone 的号码/队伍/姿态特征），本文以 part-based 表征为差异点——这是语料内唯一指向多相机 re-ID 的线索。

对跨视角的含义：visibility 门控只处理"部位缺失"，不处理同一部位跨视角的外观差异；team triplet 依赖的球衣颜色是视角不变的正面因素。

(c) 球衣号码：稀疏但唯一的强身份线索

四篇号码识别论文构成一条清晰的技术演进，并给出了对 re-ID 直接有用的经验数据。

#80 Jersey Number Recognition using Keyframe Identification（MMSports 2023，被引 23）的核心观察：SoccerNet 号码 tracklet 里 87.65% 的帧看不到号码（2,052,306 帧 → 253,350 关键帧）。KfId 模块（YOLOv5 数字检测 → 手工 RoI → 帧内 hue 直方图相关合并双位数 → 跨帧直方图聚类剔除对方球员）把 bi-LSTM 的 Test/Challenge 准确率从 30.89 / 36.07 拉到 68.53 / 73.77（按 Table 3 计算 +37.6 / +37.7，论文摘要写 +37.81），而 LSTM、TCN、ViT 三种时序模型之间的差距只有 3–10 点。序列长度 40 帧最优，更长过拟合；ColorJitter 和水平翻转会破坏号码，反而降性能。"先过滤再聚合"远胜"直接聚合"——这是语料里对时序 re-ID 最硬的一条经验。

#32 A General Framework for Jersey Number Recognition（2024）把问题重述为 Scene Text Recognition：可读性分类器（ResNet34）→ ViTPose 关节裁躯干（不需要号码框标注）→ 微调 PARSeq 逐 token 解码（能预测训练集未见的号码）。Tracklet 级加 Main Subject Filtering（Market1501 预训练的 Centroid-ReID 特征拟合高斯、迭代剔除离群帧，K=3、N=3.5，无监督，+2.89 点），再置信度加权投票。SoccerNet test 87.45 / challenge 79.31。作者发现简单投票就能打败 LSTM/TCN/transformer；ResNet34 在跨相机几何（固定广角 → 转播）迁移上优于 ViT；hockey→soccer 迁移优于反向（soccer 微调后 hockey 从 91.40 跌到 65.84）。

#35 Single-Stage Uncertainty-Aware Jersey Number Recognition（2025）取消检测阶段，直接从躯干裁剪用 ViT CLS token 预测 0–99/absent，Dirichlet 证据学习给出不确定性 u = 100/S；tracklet 聚合只保留不确定性低于阈值的帧做带均匀先验的加权平均。ViT-B/8 + 私有 200M 数据在 challenge 上 85.62（仅公开数据 83.52），test 微调版 88.27。Dirichlet 相对 softmax 在 5 种头中的 4 种提升，不可见号码检测 +5.07～+6.39。在私有 Copa America 集上最佳仅 28.07%，暴露短 tracklet、低分辨率真实转播的难度。

#37 是单帧篮球号码识别（DCNv3 + hourglass，BJN 上 49.88 vs CharNet 44.39），约 50% 的单帧精度反过来说明了 tracklet 级聚合的必要性。

但 #95 给了一个反面数据点：在球员平均高 54 px 的战术相机画面里，仅用号码分支时 Coverage 只有 0.151、MisID 0.074，加阵容约束后 Coverage 0.129、MisID 0.023（读出来的时候多半是对的，但大部分片段读不出来），而且把号码放在第一阶段硬级联反而让 CSIS 从 0.716 降到 0.709——弱模态的融合方式比有无更重要，应做 late fusion 而非 hard gating。

(d) 序列级身份：tracklet 怎么聚合、时序建模值不值

语料给出了三组彼此印证的经验数据，结论相当一致：序列信息很值钱，但显式时序模型不一定值钱。

序列长度曲线（#31，HITSZ-VCM Infrared→Visible，跨相机跨模态）：Rank-1 从 n=1 的 38.51 → n=3 53.22 → n=5 62.46 → n=7 69.88，mAP 52.77 → 55.68（6→7 帧），n≥8 饱和，n=9 部分指标回落。这是语料里最清晰的"多帧对外观模糊场景的收益"证据。深读时指出该实验把"更多帧"与"TSM 时序建模"混在一起，没有 TSM vs 纯平均池化的对照。

均值池化 vs 显式序列模型（#33，单视角跑步 re-ID）：HHCL 逐帧 2048 维特征简单平均（日间 mAP 0.940 / 夜间 0.911）稳压提出的 GRU AutoEncoder 路线（0.900 / 0.788，这一数字已含上身与鞋子颜色直方图的融合；纯 GRU AE 为 0.852 / 0.636，作者承认对画质不鲁棒）。审稿核对指出这不是受控对比：GRU AE 用 1,182/1,114 组两步序列训练，基线用按显存截断的 12,059/10,229 张单帧图，骨干与预训练也不同。#32 发现投票打败 LSTM/TCN/transformer；#88 的群体活动识别消融显示 MaxPool 在 balanced accuracy 上不逊于 Attention/TCN/BiLSTM（但后者 macro-F1 更高）；#89 发现带时序注意力训练的 MatchVision/SoccerMaster 的时序 grounding（T-IoU ≈ 15%）反而低于无时序的 SigLIP（≈ 19%）。反向的证据是 #56：号码识别冠军 ZZPM 与 J3/J5 用 tracklet transformer 做到 92.85%。所以合理的结论不是"时序模型无用"，而是任何时序模块都必须与同骨干、同数据的 mean-pooling 对照，否则无法证明其价值。

长片段 mean-pooling 已可用（#95）：45–51 s 的 fragment（约 1300–1500 帧）压成一个向量，nearest-centroid + 阈值门控，test CSIS 0.716、Coverage 0.780、MisID 0.174；主要残余错误是同队混淆，而不是聚合方式。

在此之上，语料里可复用的序列级设计有：

  • tracklet 级双策略匹配（#23 GSR 2024 冠军，GS-HOTA 63.81）：均值向量余弦（全局）+ N×M 两两相似度矩阵取最大值（局部、抗噪声 embedding），配合"号码/team 先拆分再合并 + 时间不重叠 + 物理可达"的分层规则。
  • 语义属性主导的 tracklet 切分/合并（#28 Broadcast2Pitch，GS-HOTA 61.48）：指令微调 LLaMA-3.2-Vision 一次性输出 role/jersey/color，tracklet 内多数投票决定切分，OSNet ReID 余弦距离 < 0.4 只是合并的必要条件；IDATR 使 IDF1 从 51.68 → 64.20。Table 5 的三行要一起看：PRTReID+EasyOCR+ResNet-18 组合 GS-HOTA 18.11 → CLIP+分类头 60.13 → 在 SoccerNet jersey 数据上微调 1 epoch 的 LLaMA-3.2-Vision 61.48。跳变来自换掉 OCR 式属性识别器，VLM 相对 CLIP 只多 1.35（IDF1 62.20 → 64.20）。
  • 多线索身份合并流水线（#82 SoccerFactory）：PRTReID embedding 驱动 StrongSORT，tracklet 平均 embedding + 球场坐标聚类得 team，Qwen2.5-VL 读号码，SAM2 纠 ID switch，按 ReID 与号码一致性合并碎片；在 GSR challenge 上 GS-HOTA 64.1，超过冠军 61.5。但同一篇里端到端 MOTIP 头的 AssA（53.9）低于 YOLOv8+PRTreID（58.6）——端到端关联仍弱于专门 ReID 跟踪器。
  • 目标域少量轨迹自适应（#95）：SoccerNet 预训练 PRTReID 不微调 CSIS 0.531 / Coverage 0.267；每身份 30 s 轨迹微调 → 0.652，60 s → 0.704，120 s → 0.712，收益递减。#20 补充材料 Table S1 在 SoccerNet-Tracking test 上列出 GSR 基线 AssA 49.42，而采用 test-time fine-tuning ReID 的 2023 跟踪冠军为 73.42——这是两套系统的横向对比，不是单因素消融，方向一致但幅度不能直接归因。#104 的 re-ID 前列方案把同一思路用在了 challenge set 上（推理期无监督域自适应，组织者列为共性经验之一）；TrackMerger 第一版的自监督配方在 #104 里也写得更具体：同一轨迹内取正样本、同时段存在的其它轨迹取负样本，用 triplet 微调 re-ID 网络，合并时禁止同帧重复身份与相邻帧"瞬移"。
  • 不用外观的对照（#24 TrackID3x3）：ID Switch Merging 刻意不用 ReID 特征、只按时间重叠帧数合并，去掉后 Outdoor TI-HOTA −4.83；作者指出纯外观的 tracklet 切分在同队球员间会失效。
  • 外观不可靠时的正则化（#52）：CropDrop 按球员整段序列掩码外观 embedding、强制模型依赖轨迹与上下文，整段掩码优于随机帧掩码（球轨迹 ADE 1.7179 → 1.1735 m，持球者准确率 89.56%）；Temporal Set Attention（agent 内沿时间）与 Social Set Attention（帧内跨 agent）交替的编码器是可直接借用的 tracklet 级聚合骨架。数据为 Kognia 专有。
  • 时间先验硬剪枝：#95 用首发/换人推出的在场集合 Y(t) 把 MisID 从 0.208 降到 0.174；#33 的 lap-time filtering 把"再出现最短间隔"内的候选相似度置零。这类约束零训练成本、与相机无关。
  • tracklet 净化：#80 的 GHC（跨帧直方图聚类保留多数簇）、#32 的 Main Subject Filtering、#35 的不确定性阈值、#98 的"ID count=1 + 平均关节置信度 ≥0.5"三重过滤（3,018 → 2,185 条）。

(e) 跨相机/跨视角的显式处理：语料里能找到的全部

#34 Unsupervised … multi-view similarity aggregation（Memetic Computing 2026）是语料中唯一在方法层面显式处理跨相机差异的 re-ID 论文（#103 在跨视角数据上评测，但方法里没有任何针对视角的设计，见 3.3(a)）。设计点：相似度图只允许不同相机之间建边（cos > 0.45、ambient 余弦 > 0.2）；帧级 RGB 统计 → PCA 12 维 ambient 向量做线性补偿 ẽ = L2Norm(e + aW_a) 并调制边权；按相机方位角分 8 bin 算簇的 viewpoint entropy；自定义 VDRS（只算视角不重叠的命中）与 TCP（±2 s 内的 top-5 命中）指标。报告 mAP 0.821 ± 0.037（baseline 0.694–0.739），高视角熵组 0.793 vs 低熵组 0.846。

但深读与审稿核对的共同结论是这篇不能作为参照：全文没有任何人工身份真值，mAP/purity 都以模型自己产生的伪标签为"真值"，三个 baseline 也用同一套伪标签训练；外部基准 SportsReID / CampusSport 无引用无链接；数据不公开；原文声称"跨相机同人相似度（0.78）显著高于同相机"在物理上不合理；"像素中心偏移 ≤ 40 px"在不同相机间没有几何意义；有效 crop 仅 1,669 个；消融数字在 Results 与 Discussion 中互相矛盾；审稿人还发现原文把 Margin 0.45 / Edge 0.50 称为默认配置却在该配置下报告 mAP 0.845，与主表 0.821 不一致，且正文只报告了 CMC@1 与一处 CMC@5（CMC@10 不存在）。可借用的只有思路：跨相机建边先验、viewpoint entropy 分层评估、VDRS 式指标。

#31 Progressive learning in cross-modal cross-scale fusion transformer（KBS 2024）是跨模态（RGB-IR）而非跨视角，但它的度量学习组件是语料里最接近"域对齐"的：MSRL 强制模态内正样本距离 ≈ 跨模态距离（Eq. 11–14，Euclidean 优于 cosine +2.80 Rank-1），MDL 用两模态共同的身份中心 + 动态负样本 margin（DCL_dyn 优于 DCL_hard / DCL_all）；双分支对称 cross-attention 融合比单分支 Rank-1 +6.64、比 concat +8.18；从 Conv5/6 起融合最好，往浅层加反而掉点且 FLOPs 从 4.27G 涨到 13.5G。HITSZ-VCM Infrared→Visible Rank-1 69.88 / mAP 55.68（SGIEL 67.65 / 52.30）。深读与审稿核对列出了大量自相矛盾（深读：骨干 TSM-ResNet-50 vs Swin-S、epoch 60 vs 24/32、Table 2 与 Table 3 数值完全相同、推理时缺少另一模态如何得到融合特征未说明、无公开代码；审稿新增：SYSU-MM01 表格 CAJL/CMML 两行完全相同、检测器一处写 YOLOv5 一处写 YOLOv7、Eq. 4 下标笔误且 Algorithm 1 与 Eq. 4–6 的融合流程不一致），引用其数字需谨慎。审稿核对还补了两条对跨视角读者更关键的信息：HITSZ-VCM 的 RGB 与 IR 由不同相机在不同时间采集，所谓配对帧并非时空同步（原文未说明如何配对），而 v3 的 live/replay 对恰恰是近似同步的，把"模态换成视角"时这一差异要单独论证；CCF 的 token 是 WH×d 的空间 token，融合模块内没有时间维，时序只在 TSM 骨干与最后的 logits 平均处出现。对跨视角的迁移价值：把"模态差距当域差距对齐"的 MSRL 改写成 (D_same-view − D_cross-view)² 的 view-shared refinement loss 是一个直接可试的想法；但 Eq. 6 的逐元素乘 Z_i ⊙ Z_fusion 依赖空间对齐，跨机位不成立（cross-attention 本身对 key 集合置换不变，不依赖位置对应）。

#86 SGA-INTERACT 的跨视角实验是语料里关于"2D 表征视角敏感"最直接的量化证据（类比证据：任务是骨架群体活动识别，不是 re-ID）：COMPOSER 用 3D 骨架 mAcc 47.72，前视 2D 同视角 15.23，前视训练、侧视测试降到 5.29；MPGCN 前视 2D 同视角 50.46，跨视角 4.77。其数据流水线（单视角 SOLIDER Re-ID + OCSORT → 跨视角 Re-ID 多数投票 → 三角化 → 姿态/位置启发式 3D 跟踪 → 人工修正）是一套可复用的多相机身份关联方案，但只对固定标定相机有效。

几何基础设施：标定方向的 18 篇提供了把任意转播视角投到统一球场坐标的工具（#1 TVCalib、#2 NBJW、#8 PnLCalib 均开源），但要注意 #2 在含回放/非主机位的 SN23-test 上 Acc@5 73.7% 而 CR 仅 77.5%，#8 为 78.4%——跨视角 re-ID 最需要的那 22% 的帧恰恰标不出来。#59 SoccerNet-v3D 为 v3 的 4,051 张多视角帧算好了标定并做了质量筛选（JaC_0.5% > 0.75、重投影误差、相机位移 ≥ 1 m），是现成的"带几何的跨视角图像对"。#3 提醒 homography 与富相机模型的位置可差 > 1 m，#14 指出 SN-Calib 场地尺寸不标准。两条对切入点更关键的数字：(1) 上述 JaC 都是静态单帧上的；到了转播视频（sn-gamestate 序列，#6 BroadTrack 的 Table 1）TVCalib 只有 JaC5 19.88、NBJW 37.14、BroadTrack 56.88，#28 的联合优化 69.38——在视频上做几何门控应以这一档数字为准，且只有 #6、#94、#17 三篇做了逐帧一致的时序标定（上一帧热启动 + 门控重初始化；多帧共享相机位置 + 软边界正则；Kalman 跟踪 + 顺序一致性惩罚）。(2) 球员在球场坐标里的位置怎么取，比标定器本身影响更大：#81 用姿态回归的地面关键点 mAP-LocSim 79.3，而 bbox 底边中点只有 52.4，两者图像空间 mAP 完全相同。

(g) 方向章节里的其他相关证据

  • #99 GameSight（视频理解方向）是语料里唯一把"镜头切换"当作身份问题来处理的工作：把匿名解说的 [PLAYER] 对齐到具体球员时，显式用了镜头边界/视角分类、人脸、球衣、球队归属和迭代更新的比赛状态；人类专家 Player Guessing 准确率 96.3%，其中 84.5% 依赖长镜头跟踪之外的线索（特写、中景切换）。这是跨视角身份关联最直接的动机证据。
  • #84 FOOTPASS 的生产级多趟跟踪给出了一份工业界身份线索清单（队伍、球衣号 + 名单约束、颜色直方图、深度特征、IoU/距离、角色先验）；其 DST 在行为球员无 bbox 时仍有 33.4% 召回（纯视觉 TAAD 3.9%），说明战术/时序先验能补偿外观缺失。数据上提供 54 场全场的 single-player tracklets + jersey/team，并统计了直播/回放分段（46.8% 的界外球发生在回放中）。
  • #48 X-VARS：单视角微调 CLIP（Acc 0.52）超过多视角 VARS（0.43）——多视角融合不会自动更好，任何跨视角实验都应先设一个强单视角基线。

  • #40 Beyond the Premier：train-on-one-domain / test-on-all 的相机类型矩阵评测，结论是端到端时序模型抗域漂移、冻结特征 + 池化崩溃（到 AI 导播域 tight-AmAP 最高仅 5.08%）。
  • #67 教材章节给出 image-level / tracklet-level / open-world 三级 re-ID 设置，可用来给 3.4 表的"序列"列一个统一定义。
  • #35 与 #56 的 UniBw 方案都把 v3 ReID 的 350,986 张球员裁剪图当作无标签图像池做伪标注——v3 的身份标注被丢弃、只用其图像，与切入点 6 的弱监督思路相关。
  • #104 里两条容易被忽略的旁证：pitch localization 的参赛者 P7 按相机视角把 v3 数据拆成若干子集、分别训练分割模型，理由是不同视角下场地元素的相对位置不同——这是语料里少数"按视角类型条件化"被实际采用的例子（无消融数字）；标定冠军直接复用自己的场地特征检测结果，组织者承认两项任务强耦合。
  • #105（action spotting 书章）把 2018–2024 年足球视频的时序建模手段（NetVLAD++ 时序池化、TSM/GSM/GSF 时序移位、GRU、transformer）整理成一条线，结论与 #40、#42 一致：端到端微调的时空骨干在 tight 指标上全面超过"冻结特征 + 池化"。与身份无关，但对 tracklet 编码器选哪种训练方式有参考意义。

(f) 姿态/骨架作为外观正交的身份线索

#98 用 YOLOv5 + ByteTrack + HRNet 提 21 帧 2D 骨架序列做持球者识别，与身份无关，但两个发现可迁移：逐帧以髋中点重定位（Re-centered）单独带来 +5.3～+8.3 的准确率（零额外 FLOPs），单独尺度归一反而伤害（−2.5～−4.1），组合最优；2D 骨架本身视角相关，镜像增强还会混淆左右。#33 的 GRU AE 证明跑动动态在清晰画面下能区分穿同款衣服和鞋的跑者（单 query AP 0.841 vs 颜色 0.677），但对模糊极敏感。语料里没有任何工作把骨架/步态特征与外观 re-ID 融合来做球员身份。

3.6 小结

  • 有可用基线：单视角短时程 re-ID（PRTreID mAP 72.59，但评测协议未交代；同视角篮球小挑战集饱和到 0.98）；tracklet 级号码识别（test 87–88）；把单机位转播投影到球场坐标（静态主机位帧 JaC10 > 90；视频序列上 JaC5 只有 57–69）。
  • 部分解决：v3 直播↔回放单帧配对（challenge 集成 mAP 93、单模型 test mAP 85–87；候选池小，方法论文只有 #103 一篇且未处理视角）；单机位长时程身份（CSIS 0.72，需逐场微调）；非主机位标定（CR ~78%）。
  • 没人做：跨视角 + 序列的球员 re-ID；按视角差分桶的 v3 评测（#103 与两届挑战赛都只报告总体数字）；把 v3 的多视角对应与场地标定联合使用（#3 仅提出设想）；视角不变的外观/部件表征（PRTreID 只处理缺失）；骨架/步态与外观的融合；带真值的多相机 RGB 序列基准。

本方向共 11 篇，是语料中与"球员身份"最直接相关的一组，但其内部结构相当异质：真正以 re-ID 为核心任务的只有 5 篇（#30、#31、#33、#34、#103，其中 #31 是可见光–红外行人 re-ID，#33、#34 面向跑步/休闲运动，只有 #103 在 SoccerNet-v3 的跨视角 re-ID 数据上做实验），另有 1 篇长时程球员身份分配基准（#95）；球衣号码识别（jersey number recognition, JNR）4 篇（#80、#37、#32、#35）；还有 1 篇以骨架序列识别"持球球员"的工作（#98），其"identification"指的是角色判定而非身份匹配。时间上，2023 年的工作（#30 PRTreID、#80 关键帧 JNR、#37 DHN）分别奠定了"多任务 part-based 球员表征"和"tracklet 级号码识别"两条线；2024 年 #32 用预训练 STR 模型把 SoccerNet JNR 的 test 精度从 68.53% 拉到 87.45%，#103 以改进的 Swin 骨干在 v3 ReID 上给出单模型基准，#33 与 #31 则探索序列级动态特征；2025 年 #35 以单阶段 ViT + Dirichlet 不确定性再刷新 challenge 集，#98 转向骨架时序；2026 年 #95 把问题推到"整场比赛的长时程 track 级身份分配"并给出弃权感知的评测协议，#34 则尝试无监督多相机聚类。可以看到主要子问题有三个：(1) 如何从 tracklet 中筛掉无效帧再做聚合；(2) 球衣号码作为强身份线索如何与外观 re-ID 互补；(3) 面向长时程、跨相机场景时如何设计训练与评测协议。

代表性工作

(a) 球衣号码识别：从专用分类网络到预训练 STR，再到不确定性建模

「#80 Jersey Number Recognition using Keyframe Identification from Low-Resolution Broadcast Videos（2023）」指出 tracklet 中绝大多数帧不含可见号码——KfId 模块把 2,052,306 帧筛到 253,350 帧（减少 87.65%）。其做法是先用 SoccerNet 上微调的 YOLOv5 检测数字，再经手工 RoI 过滤、帧内局部直方图相关（LHC）合并双位数字、跨帧全局直方图聚类（GHC）剔除对方球员号码，最后从关键帧采样 40 帧送入 ResNet-18 + bi-LSTM 做 digit-wise 分类。KfId 使 bi-LSTM 的 Test/Challenge 准确率从 30.89/36.07 升至 68.53/73.77（按表计算 +37.64/+37.70，论文摘要写 +37.81），超过 Vats et al. transformer 方法的 52.91/58.45；序列长度消融显示 40 帧最优，更长反而过拟合；标准数据增强（ColorJitter、翻转）会破坏号码本身而降低性能。

「#32 A General Framework for Jersey Number Recognition in Sports Video（2024）」把 JNR 视为 Scene Text Recognition 特例：可读性分类器（ResNet34）→ ViTPose 关键点裁剪躯干（无需号码框标注）→ 微调的 PARSeq 逐 token 解码（可预测训练集未出现的号码）。Tracklet 级新增 Main Subject Filtering，用 Market1501 上训练的 Centroid-ReID 特征拟合高斯并迭代剔除离群帧（K=3, N=3.5），再以置信度加权投票聚合。在 SoccerNet JNR 上取得 test 87.45% / challenge 79.31%，远超 #80 的 68.53%/73.77%；同时发布一个 132,983 张裁剪图（4,250 张带号码标签）的冰球数据集，PARSeq 微调后图像级精度 91.4%。跨运动实验显示 hockey→soccer 迁移优于反向（soccer 微调后 hockey 从 91.40% 跌到 65.84%）。值得注意的是作者发现简单投票即可击败 LSTM/TCN/transformer 类时序模型。

「#35 Single-Stage Uncertainty-Aware Jersey Number Recognition in Soccer（2025）」取消号码检测阶段，直接以 ViT 的 CLS token 预测 0–99 或 absent，并用 Dirichlet 证据式学习输出不确定性 u=100/S；提出 tied digit-aware（TDA）头，跨位置共享数字权重、参数比独立 101 类头少 86%。Tracklet 聚合只保留不确定性低于阈值的帧做带均匀先验的加权平均，全部帧都不确定则判为无号码。Dirichlet 相对 softmax 在 5 种头中的 4 种提升总准确率（IND +5.01、TDA-MB +4.30），不可见号码检测提升 +5.07～+6.39。最终 ViT-B/8 配私有 200M 数据在 Challenge 上达 85.62%（超过 #32 的 79.31%），仅用公开数据为 83.52%；Test 上微调版 88.27%。在私有 Copa America 集上最佳仅 28.07%，暴露短 tracklet、低分辨率真实转播的难度。

「#37 Occluded and Deformed Jersey Numbers Recognition by Hourglass Networks with Deformable Convolutional Networks（2023）」是单帧篮球号码识别，在 CharNet 中引入 DCNv3，在自建 BJN 数据集（3,012 张）上 Accuracy 从 44.39 升至 49.88，SynthText 上几乎无变化；仅与 CharNet 一个基线对比。其约 50% 的单帧精度反过来说明了 tracklet 级聚合的必要性。

(b) 球员 re-ID 与长时程身份分配

「#30 Multi-task Learning for Joint Re-identification, Team Affiliation, and Role Classification for Sports Visual Tracking (PRTreID)（2023）」在 BPBReID（HRNet-W32，K=5 个身体部位、带可见性分数）基础上加入 role 分类头（Focal loss）与 team affiliation triplet loss（仅对 player 生效），推理时以两簇 K-means 得到队伍标签而不依赖预定义队伍。在由 SoccerNet-Tracking 裁剪自建的 re-ID 集上 mAP 72.59 / R1 89.57（BPBReID 71.43/89.31，BoT 62.63/80.24）；team 检索 mAP 92.89；三任务联合使 K-means 队伍分类准确率从 91.87% 升至 95.6%。消融显示仅 team 或仅 role 目标会让 re-ID 崩溃（mAP 约 10–12）。跟踪侧提供了带可见性权重的 per-part EMA tracklet 聚合和基于 part 外观代价的离线 tracklet 合并。

「#103 An Enhanced Swin Transformer for Soccer Player Re-identification（RFES-ReID，2024）」是本组、也是整个语料里唯一在 SoccerNet-v3 跨视角 re-ID 数据上做方法研究的论文。骨干为 Swin-T，在每个 stage 前插入 Regional Feature Extraction Block（把 token 还原成特征图，过 3×3 空洞卷积 + GELU 后残差相加，再展平），以补足 Transformer 对低分辨率小目标的局部特征；损失为交叉熵 + triplet（margin 0.3）+ focal（γ=2），检索阶段加 k-reciprocal 重排序。训练前删掉图像少于 4 张的身份，batch 为 8 个身份 × 4 张。只用 train split 训练，在 test split（query 11,777 / gallery 34,989，逐 action 检索）上：Swin-T 基线 R-1 75.3 / mAP 80.2 → +RFEB 79.6 / 81.4 → +融合损失 81.8 / 85.0 → +重排序 84.1 / 86.7；同表对比 OSNet 69.2 / 76.4、TransReID（ViT-B/16）68.6 / 77.2、TransReID-SSL 83.8 / 80.1、Sports Re-ID 81.5 / 86.0。Market-1501 上 96.2 / 89.1。需要注意：对比行的来源未说明，ResNet50 行 48.4 / 59.1 与 2022 挑战赛 challenge 集官方 baseline（#104）数值相同，疑似混用 split；正文与 Table 1 在 Market-1501 上的数字不一致（95.10 / 86.97 vs 95.7 / 87.3）；方法对视角变化没有任何设计，作者把 perspective difference 留作未来工作；全部单帧。

「#95 LTPI: A Benchmark for Long-term Player Identification from Single-Camera Football Video（2026）」形式化了整场比赛（101 分钟）的 track 级身份分配任务：3,087 个可见性片段，允许弃权（UNK），并利用首发阵容与换人推出的"时刻 t 在场球员集合 Y(t)"剪枝候选。评测采用代价敏感的 CSIS（错误代价 1、弃权 0.5）配合 Coverage/MisID，按时间顺序取每位球员前 ≥60 s 的片段做训练、上半场验证、下半场测试。基线用 PRTreID（SoccerNet 配置）做 match-specific 微调 + mean-pooling，CSIS 从不微调的 0.531 升到 0.704，加阵容约束 0.716；球衣号码分支（Koshkina & Elder STR）因球员平均高仅 54 px 覆盖率只有 0.151，把号码放在第一阶段反而拉低 CSIS（0.709）。主要误识别发生在同队球员之间。

「#33 Runner re-identification from single-view running video in the open-world setting（2024）」在无标注固定机位跑步视频上做端到端 re-ID，提出 GRU AutoEncoder 无监督学习跑动动态特征，并以全身 + 鞋子局部的 HHCL 双模型（3:1 加权）取得日间 mAP 0.944、夜间 0.915；GRU AE 夜间 mAP 仅 0.636，动态特征对画质退化不鲁棒。「#34 Unsupervised research on multi-view similarity aggregation and multi-level gap optimisation ...（2026）」在自采 12 相机休闲运动数据上做无监督跨相机聚类（只在不同相机间建边、边权融合光照统计向量），报告 mAP 0.821，但数据不公开、外部基准无法核实、基线为 2017–2019 方法复现，数值不宜作为参照。「#31 Progressive learning in cross-modal cross-scale fusion transformer for visible-infrared video-based person reidentification（2024）」是通用 RGB-IR 视频 re-ID，TSM+ResNet-50 双流加跨尺度 cross-attention 融合，HITSZ-VCM 上 Rank-1 69.88 / mAP 55.68；其 tracklet 长度消融（n=1 时 38.51% → n=7 时 69.88%，n≥8 饱和）是本组中最清晰的序列长度证据。

(c) 骨架时序

「#98 Skeleton-Based Approach for On-the-Ball Player Identification on Broadcast Soccer Videos（2025）」以 YOLOv5 + ByteTrack + HRNet 提取 21 帧 2D 骨架序列，用 STGCN/2s-AGCN/STGCN++ 做持球/非持球二分类，最佳 On-the-ball accuracy 86.70%，仅需像素级 DenseNet-201+LSTM 的 0.53% FLOPs、推理快 32.37 倍；提出 Re-centered/Resized 骨架归一化。ByteTrack 无 ID 切换的成功率仅 75.4%，作者把多机位融合列为未来方向。

对 SoccerNet-v3 的使用

11 篇中只有 #103 直接使用了 SoccerNet-v3 的 re-ID 身份标注（直播↔回放的跨视角对应）：官方 train split 训练、test split 评测；但它没有引用 v3 的数据论文，SoccerNet-v3 ReID 的出处写的是 challenge 网页和 SoccerNet-v2 论文，所以不在任何引用列表里。其余 10 篇都没有用到多视角对应、re-ID 身份标注或场地线标定，大多数引用属于"SoccerNet 项目总引用"。具体而言：#80、#32、#35 使用的是 SoccerNet 2023 Jersey Number Recognition 挑战赛的 4,064 条 tracklet 数据，但把引用统一归到 v3 的 Scientific Data 论文；#35 另外使用 SoccerNet ReID 的 350,986 张球员裁剪图（源自 v3 的 re-ID 标注）作为号码伪标注的额外训练数据，丢弃了身份标签。#30 明确拒绝 SoccerNet-ReID，理由是它只含同一动作的跨相机图像、无视频与跨动作标注，转而从单主摄像机的 SoccerNet-Tracking 自建 re-ID 集。#95 只间接使用：其 PRTReID 与 STR 模型在 SoccerNet 上预训练，并把检测框尺寸与 SoccerNet-GS 对比。#98 使用 SoccerNet 原始转播视频（40 场）自建触球剪辑。#31、#33、#34、#37 均为背景引用；#37 甚至称 SoccerNet-v3 "只有视频无法输入图像框架"，与该数据集以回放帧发布的事实不符。所有 11 篇 read_ok 均为 true。

对"换视角 re-ID + 时序"方向的可借鉴点

本组与跨视角匹配本身的交集很少——除 #103 外没有一篇做同一时刻多视角检索（#34 有跨相机但可信度存疑，#31 是跨模态而非跨视角），而 #103 虽然在跨视角数据上评测，方法上并未针对视角；但在"tracklet 级身份"上有若干可直接复用的设计：

  1. 先净化再聚合：#80 的 KfId（约 +37.6 个百分点）、#32 的 Main Subject Filtering（+2.89）、#35 的不确定性阈值聚合三者一致表明，tracklet 中无效帧是主要噪声源；在 video re-ID 特征聚合前加入可见性/质量/不确定性门控，比换更复杂的时序骨干更划算。#80 的 GHC（跨帧直方图聚类保留多数簇）是一种廉价的 tracklet 内身份一致性约束，可用于跨视角匹配前的 tracklet 净化。
  2. 简单聚合往往足够：#32 投票击败 LSTM/TCN/transformer，#33 中 mean-pooling 的 HHCL 强于 GRU AE，#95 基线也只用 mean-pooling；显式时序建模需要更强表征才有收益。序列长度上 #80（25 fps 号码 tracklet，40 帧最优）与 #31（每 5 帧抽 1，n=7 最优、n≥8 饱和）各给出一个参考值，采样率不同，不宜合成区间。
  3. 视角鲁棒的表征：#30 的 part-based + 可见性感知距离（只对双方可见部位求平均）天然应对视角变化导致的部位缺失，team/role 辅助目标是视角不变的强先验；#31 的 MSRL（模态内距离≈跨模态距离）可改写为"同视角≈跨视角"的对齐损失；#98 的骨架归一化为姿态/步态类视角不变特征提供起点。
  4. 号码作为跨视角硬约束：#32、#35 的流水线全部基于公开预训练模型，#35 的不确定性输出便于在号码不可见的视角弃权、只在高置信帧上做硬约束或重排序。但 #95 提醒在小目标下号码覆盖率可能极低（0.151）。
  5. 评测与时间先验：#95 的时间顺序划分、上半场验证/下半场测试、CSIS/Coverage/MisID 三指标适合评估长时漂移下的稳健性，Y(t) 式候选剪枝与 #33 的 lap time filtering 提示 SoccerNet-v3 的直播/回放时间戳可构造类似约束；#34 的视角熵分层与 VDRS/TCP 指标可作跨视角一致性评估参考。#95 数据、代码与 checkpoint 公开，可作为在 SoccerNet-v3 上训练的模型的长时程泛化测试集。
  6. v3 单模型基线表：#103 的 Table 4 给出了 CNN / ViT / DeiT / Swin 多种骨干在 v3 ReID test split 上的同表数字；重排序带来 +2.3 R-1 / +1.7 mAP，说明 action 内 gallery 的近邻结构可以利用；"删少样本身份 + focal loss"是应对 v3 每身份样本极少的廉价手段。引用前注意该表各行来源未说明。

开放问题

  • 跨视角空白：SoccerNet-v3 的多视角 re-ID 标注在本组中除 #103 外都被绕过甚至拒绝（#30）；#103 也只报告总体数字，没有按视角差分桶，视角不变性留作未来工作；号码识别与长时程识别均只在单相机上验证，跨视角下"净化–聚合–号码约束"的组合效果无人报告。
  • Test/Challenge 与真实转播的落差：#32 79.31 vs 87.45、#35 Copa America 仅 28.07%、#95 单场比赛，域偏移与短 tracklet 问题未解决；#95 还需逐场微调 PRTreID（CSIS 0.531→0.704），生产可用性受限。
  • 时序建模缺位：#35、#95 都把"tracklet 上的时序建模"列为未来工作，#98 的骨架序列与 #33 的动态特征尚未与外观 re-ID 结合。
  • 可复现性：#35 最佳结果依赖私有 200M 数据，#34 数据与外部基准不可核实，#37 无消融，#95 的号码/球队微调数据不公开。
  • 同队相似球员：#95 的 t-SNE 显示队内簇重叠是主要错误源，而号码在小目标下几乎不可读，需要更细粒度的局部线索（如 #33 的鞋子式部件）或跨视角互补信息。

检测、跟踪与球场状态重建 14 篇

概览

本方向共 14 篇，是语料中最贴近"从原始转播画面到结构化球场信息"这一底层流水线的一组工作，覆盖三个层次：单帧的球员/球检测与分割、视频级的多目标跟踪（MOT），以及把跟踪结果映射到球场真实坐标并附带身份属性的 Game State Reconstruction（GSR）。时间上呈现清晰的演进脉络：2022 年以数据集与基准建设为主（「#18 SoccerNet-Tracking」提出足球 MOT 基准，「#19」建立 SoccerNet-v3 上首个检测基准）；2023 年出现面向远景小目标与遮挡实例的检测/分割基线（#22、#93）；2024 年「#20 SoccerNet GSR」把检测、跟踪、re-ID、球场标定和身份属性识别整合为一个端到端任务并定义 GS-HOTA 指标；2025–2026 年则分化为两条线——一条在 GSR 基准上做系统级冲榜（#23、#28）并把范式外推到篮球/排球（#24、#29），另一条回到检测前端，用超分辨率（#26）、频域滤波与 MoE（#27）、轻量 YOLO+ByteTrack 工程系统（#25）解决转播远景中球员/球只有几个像素的问题。

主要子问题可归纳为：(a) 标注稀缺与远景小目标下的检测；(b) 同队外观相似、遮挡与相机运动导致的 tracklet 碎片化与 ID switch；(c) 球场配准/相机标定，把像素坐标转换到视角无关的球场坐标；(d) 以 role / team / jersey number 为核心的身份属性识别及其与跟踪的融合。值得注意的是，尽管本方向多篇工作都包含 re-ID 组件，但所有 14 篇均为单相机/单视角设定，没有任何一篇处理跨相机或换视角的身份对应。

代表性工作

2.1 数据集与基准

「#18 SoccerNet-Tracking: Multiple Object Tracking Dataset and Benchmark in Soccer Videos（2022）」是本方向的基石。数据来自 2019 Swiss Super League 12 场比赛的单主摄像机 1080p/25fps 视频（非广播视频，无镜头切换），围绕 SoccerNet-v2 动作点抽取 200 段 30 s 片段外加一个完整 45 分钟半场，共 225,375 帧、5,009 条 tracklets、3,645,661 个框；标注 player/goalkeeper/referee/ball/other 五类，球员额外带队伍侧与球衣号码（96% 有号码）。其关键设计是目标离开画面后回归仍保持同一 ID，使其成为长时 re-ID 的 sandbox。基准显示通用行人跟踪器直接迁移效果有限：w/o GT 下 DeepSORT HOTA 36.66 → FairMOT 43.91 → ByteTrack 47.23；在其 train 上微调 FairMOT 后 HOTA 升至 57.88（提升约 14 点，主要来自去除观众误检与学会检测球）。逐类分析表明 corner 等球员交叉场景 AssA 最低（w/ GT 49.6），而 penalty、goal 等密集场景瓶颈在检测（DetA 20.1 / 29.6）。

「#20 SoccerNet Game State Reconstruction: End-to-End Athlete Tracking and Identification on a Minimap（2024）」在 SoccerNet-Tracking 的 200 段片段上扩展了 9.37M 球场线点与 2.36M 带 role/team/jersey/track id 的球场位置标注，正式定义 GSR 任务与 GS-HOTA 指标（LocSim × IdSim）。基于 TrackLab 的模块化基线 GSR-Baseline 采用 YOLOv8 + StrongSORT + PRTreID（多任务 identity/team/role 嵌入）+ MMOCR + TVCalib，test GS-HOTA 仅 22.26%（challenge 23.36%）。指标成分消融揭示瓶颈顺序：图像空间 HOTA 57.64 → 加 pitch 42.65 → 加 jersey 后跌至 25.65，即球衣号码识别是最大瓶颈，其次是 pitch 定位；模块 oracle 消融中 ReID (PRTreID) 及下游可达 87.42，而 BBox Det 仅 35.28。整条流水线在 A100 上 1.1 FPS。

「#24 TrackID3x3（2025）」把 GSR 简化为固定相机、6 名球员、手工场地关键点的 Track-ID 任务并推广到 3x3 篮球，发布 Indoor/Outdoor/Drone 三个子集共 277,926 帧并附 10 点姿态标注；基线用 CAMELTrack + YOLOX，ID Switch Merging 模块刻意不用 ReID 特征，只按时间重叠帧数合并，Indoor TI-HOTA 85.53%、Outdoor 71.03%（去掉合并模块后 Outdoor 降 4.83 点）。作者明确指出仅靠外观的 tracklet 切分在同队球员间会失效。

2.2 单帧检测与分割前端

「#19 Semi-Supervised Training to Improve Player and Ball Detection in Soccer（2022）」用 SoccerNet-v3 的框标注（6 类，超过 250,000 个 GT 框）作为标注集，SoccerNet-v1 视频按 1 fps 抽帧得到 1,596,387 张未标注帧，做迭代 teacher-student 自训练（Faster R-CNN + FPN + ResNet-50）。核心是伪标签的双阈值 "doubt" 加权：置信度落在 [τl, τh) 的提议损失权重置 0。1% 标注下 mAP 从 18.1 升至 26.2，100% 标注下 52.7 → 53.8；最终在 test 集给出 SoccerNet-v3 首个检测基准 mAP 52.3%。实验还得出"低于约 0.8 的检测应当作负样本而非忽略"和"训练后在真实标注上 fine-tune 很关键"两条经验结论。

「#22 Setting a Baseline for Long-Shot Real-Time Player and Ball Detection in Soccer Videos（2023）」从 SoccerNet-v3 中按"最大人物框高 ≤ 250 px"筛出远景子集 SoccerNet_v3_H250（14,368/2,726/2,692），把 7 类人物合并为 person，在统一硬件上比较 FootAndBall 与 YOLOv8n：微调后 YOLOv8n 的 person AP11 达 0.9058（FootAndBall 仅 0.3905）；输入分辨率 640→1200 使 ball AP11 从 0.3093 升至 0.5361，推理仍在 7–10 ms/帧。

「#26 A region-guided super-resolution reconstruction algorithm for player and ball detection（2026）」沿用上述 H250 子集，提出 RGSRR：EDSR 风格残差主干 + DySample 动态上采样，用标注框膨胀后的前景权重图做区域加权 L1 与边缘一致性损失，并用轻量质量估计器对特征做 FiLM 调制；LeYOLO 检测器上 mAP@0.5 从直接 LR 输入的 53.1 升至 74.5（EDSR 前端 70.1），AP_ball 从 27.1 升至 51.2。「#27 Restoring Geometric and Probabilistic Symmetry for Tiny Football Localization（2026）」则专攻平均仅 18.8 px 的足球：GOAL 检测器在 DINOv3-Tiny 双流骨干上加入频域 Spectral Gating 抑制草坪周期纹理、异构 MG-MoE 分别处理清晰与运动模糊的球、以及 IGDE 高斯热图辅助头，并发布 14,773 张的 Soccer-Wild 数据集；mAP 40.0 较 DEIM-R50 的 32.6 提升 7.4，参数仅 12.41M。「#93 Image- and Instance-Level Data Augmentation for Occluded Instance Segmentation（2023）」是篮球实例分割挑战赛报告，用 HTC + CBSwin-Base 配合提出的 Balanced Occlusion Aware Copy-Paste 把遮挡实例整组粘贴到无遮挡图像，Occlusion Metric 0.451 获第一阶段第一，并发现 Soft-NMS 等提升 seg_mAP 的后处理反而损害 OM。

「#106 A Deep Learning Framework for Soccer Object Detection and Event Recognition（2025）」是一篇会议短文，做了两条互不相连的单帧流水线。检测侧比较 YOLOv8/v9/v11，并把球单独交给一个 YOLOv11、其余类别交给 YOLOv9c：球员/门将/裁判 mAP50 93.7%，球在 SoccerNet-Tracking 上只有 55%（mAP50-95 38.5，FootAndBall 为 23.62），在 #22/#26 的 H250 子集上 73.7、SoccerSum 上 80.4、RoboFlow 上 96%。事件侧用微调的 EfficientNetB0 做 7 类单帧图像分类，测试 accuracy 91.69%，拿到 SoccerNet v3 的三类事件帧上推理为 71.43%（论文结论段把它写成 mAP，按表格应为 accuracy）。论文把 SoccerNet-Tracking 称为"SoccerNet v2"，无消融、无代码。

2.3 单视角跟踪系统

「#21 MV-Soccer（2024）」把 H.264/H.265 码流中的压缩域 motion vector 与 RGB 堆叠作为 YOLO 式分割网络输入，并用逐目标运动向量做框中心补偿；在 DFL + SoccerNet-Tracking 子集 + 私有 SoccerPro 合并数据上 mask mAP 0.78（YOLOv8x-seg 0.74），MOT17 val HOTA 64.9 / 28.7 FPS。但其消融表与主表数字完全重合、方法细节缺失，结果可信度需谨慎对待。「#25 AI-Based Football Player Detection and Tracking System（2026）」是工程系统：在 SoccerNet-v3 五类框标注（149,639 实例）上训练 YOLOv8，配 ByteTrack 且明确不用外观特征，750 帧片段上 MOTA 0.59、Recall 0.62、ID switch 111 次，GTX 1650 上 9.8 FPS——为"无外观跟踪在密集足球场景中失效"提供了一个量化对照。

2.4 完整 GSR 系统

「#23 From Broadcast to Minimap: Achieving State-of-the-Art SoccerNet Game State Reconstruction（2025）」是 GSR Challenge 2024 冠军：三阶段流水线（raw tracking → team detection → post-processing）。球场定位用 SegFormer 直接回归 7 个相机参数再以 74 个关键点暴力精修；ReID 用 ResNet50 + TripletLoss（自建 280k crops/370 名球员），TeamID 用 OSNet 学 111 种球衣类别；DeepSORT 在球场世界坐标而非像素坐标中运行，并加朝向与 TeamID 约束；后处理以球衣号码/team 先拆分再合并 tracklet，合并同时用均值向量余弦距离与 N×M 两两相似度矩阵最大值双策略。GS-HOTA 63.81，远超第二名 43.15 与官方基线 23.36；GS-AssA 82.23 归因于 tracklet 合并。缺点是无消融、训练数据全部内部自建。

「#28 Broadcast2Pitch（2026）」以 YOLOX + DeepEIoU（OSNet 特征）为骨干，球场配准联合预测 97 个关键点与 18 条线并用线/中圈/关键点统一最小二乘求解（JaC5 69.38 / JaC10 92.84，对比 TVCalib JaC5 19.88）；身份识别改为指令微调 LLaMA-3.2-Vision 一次性输出 role/jersey/color，仅微调 1 epoch 即优于 PRTreID+EasyOCR 组合（GS-HOTA 61.48 vs 18.11）；IDATR 模块把 VLM 语义属性的 tracklet 内多数投票作为切分/合并的主判据，ReID 余弦距离 < 0.4 只是合并的必要条件。消融显示 IDATR 使 IDF1 从 51.68 升至 64.20，最终 GS-HOTA 61.48。「#29 Jump-Aware（2025）」把同类流水线用于篮球/排球，用 MGMAE 视频编码器在 tracklet 16 帧序列上定位起跳/落地帧（mAP@δ=3 95.33），修正腾空时单应映射的位置畸变，并用 Florence-2-B 做球衣号码识别；跨项目迁移时号码识别准确率从 84.69% 降到 69.29%，位置校正部分缺乏定量评价。

对 SoccerNet-v3 的使用

真正使用 v3 数据的有 5 篇，且全部只用了其单帧 2D 框标注：#19 用其 344,660 个人体框与 26,939 个物体框建立检测基准；#22 与 #26 筛出远景子集 H250（两类：ball/person）；#25 抽取五类共 149,639 个实例训练 YOLOv8；#28 与 #29 把 v3 论文当作 "SoccerNet jersey dataset" 的出处，用球衣号码 tracklet 裁剪图微调 VLM（#29 还人工补充了角色与球衣颜色标注）。#20 在标注协议层面沿用了 v3 的球场线标注方式（沿线放置点序列、26 类线段），但数据本身来自 SoccerNet-Tracking。补充的 #106 属于间接使用：球检测在 H250 子集上做跨数据集评测，事件分类器在 v3 的三类事件帧上做了一次推理；它没有引用 v3 的数据论文，出处只写了 SoccerNet 网页。其余 6 篇（#18、#21、#23、#24、#27、#93）仅作背景引用，#27 甚至把 v3 与 SoccerNet-Tracking 混淆。没有任何一篇使用 v3 的多视角回放对应关系、跨视角 re-ID 标注或场地线标定数据——这是本方向与读者课题之间最显著的空白。

对"换视角 re-ID + 时序"的可借鉴点

本方向与"换视角"本身交集很少，但在"时序身份建模"和"共享坐标系"上有几条具体可复用的线索：

  • 球场坐标作为视角不变的空间先验。 #23 在世界坐标中运行 DeepSORT、#28 与 #29 把 tracklet 底边中点投影到俯视球场坐标，本质上用相机标定消除了转播相机运动带来的几何视角变化。SoccerNet-v3 恰好同时提供多视角对应与场地线标注，可把"live 帧与 replay 帧投影到同一球场坐标后的位置一致性"作为跨视角匹配的硬约束或弱监督信号；#20 的 GS-HOTA（LocSim × IdSim）可直接推广为共享坐标系下的跨相机身份评测。
  • 语义身份属性 + 外观 + 时空约束的分层 tracklet 关联。 #28 的 IDATR 与 #23 的后处理都用球衣号码/team/role 先拆分再合并，ReID 距离退为必要条件；#24 的时间重叠合并与颜色直方图中值也提供廉价对照基线。这套逻辑可迁移到跨视角 gallery 聚合，把"物理可达性"换成跨相机时间窗。#28、#29 进一步表明指令微调 VLM 可作为几乎视角无关的号码/颜色/角色提取器。
  • tracklet 级序列特征。 #23 的均值余弦 + N×M 两两最大相似度双策略、#20 补充材料 Table S1 把 GSR 基线（AssA 49.42）与采用 test-time fine-tuning ReID 的 2023 跟踪冠军（73.42）并列（两套系统的横向对比，不是消融）、#29 用 MGMAE 编码 16 帧序列，都是"序列 vs 序列"匹配的直接起点；#21 的压缩域 motion vector 则是零成本的短时运动线索。
  • 数据资源。 #18 的 5,009 条 25 fps tracklets（96% 带号码、含队伍侧、离场回归保 ID）是把 v3 单帧多视角 re-ID 扩展为时序样本的现成来源，其 w/ GT 协议可剥离检测误差只评关联；#19 的 1.6M 未标注帧管线与双阈值 doubt 加权可迁移到跨视角伪匹配对的软加权自训练；#22/#26 的 H250 子集和退化协议（模糊 + ×2 下采样 + 压缩）可用于模拟远景 vs 近景回放的分辨率差异。
  • 上游检测器与遮挡增强。 #19（Faster R-CNN，mAP 52.3）、#22（YOLOv8n，7–10 ms）、#25（YOLOv8 五类）给出了在 SoccerNet-v3 帧上现成的球员框生成方案；#93 的遮挡感知 Copy-Paste 可用于模拟转播中球员互相遮挡以增强外观特征鲁棒性，其"通用 mAP 与下游指标优化方向不一致"的观察也提醒应以 re-ID 指标选择检测后处理。

开放问题

  1. 跨视角完全空白。 全部 14 篇均为单相机设定；GSR 系列的 team 仅相对相机视角定义左右，无法直接跨镜头切换保持一致。SoccerNet-v3 已有的多视角对应标注与 GSR 的球场坐标标注尚未被任何工作联合使用。
  2. 身份属性是 GSR 的最大瓶颈。 #20 显示加入 jersey 后 GS-HOTA 从 42.65 跌至 25.65；#29 表明号码识别跨项目迁移损失超过 15 个百分点；#28 的 VLM 方案计算开销大、相对 CLIP 提升有限（61.48 vs 60.13）。远景小尺寸、遮挡下的号码识别与外观 re-ID 如何互补仍无定论。
  3. 长时与同队区分。 #18 的 45 分钟半场只在私有 challenge 集评测，正文无长时定量结果；#24 与 #23 都指出同队球员交叉时的 ID 互换是 AssA 下降主因，而现有合并规则（时间重叠、硬阈值）不能处理互换。
  4. 可复现性与消融缺失。 #23 无任何消融且训练数据全部内部自建；#21 消融数字与主表重合；#29 位置校正无定量评价。GSR 冠军方案与开源基线之间 40 点的 GS-HOTA 差距中，各模块贡献并不清楚。
  5. 实时性。 #20 基线 1.1 FPS，#28 依赖 LLaMA-3.2-Vision，#27 仅 28 FPS；只有 #23 的 raw tracking 阶段（80 FPS）和 #22/#25 的轻量检测器接近实时，而后者恰恰放弃了外观 re-ID。
  6. 检测前端与时序的割裂。 #19、#27 都在结论中指出单帧框架缺乏时序记忆并把视频/时序建模列为未来工作，但本方向内尚无工作把时序线索反馈回检测端。

相机标定与场地配准 18 篇

概览

本方向共 18 篇，是语料中与 SoccerNet-v3 关系最"单一"的一类：几乎所有工作只使用 SoccerNet-v3 的场地线（pitch line）/球门柱 polyline 标注，即 SoccerNetV3-Calibration（SN-Calib，2022 版 20,028–21,132 张，2023 版 22,816–25,506 张，含主机位以外的多机位帧），不触及其 re-ID 或跨视角对应标注。时间演进清晰：2023 年以 #1 TVCalib 为代表，把 homography 估计重新定义为可微的相机参数优化问题，并配套两篇综述（#4、#10 属同期衍生应用）；2024 年转向"从 SN-Calib 线标注派生密集关键点 + HRNet 热图"的 3D 标定路线（#5、#2），同时 #3 提出统一评测协议 JaC，#12 质疑固定 FIFA 模板；2025 年出现时序化的相机跟踪（#6 BroadTrack）、困难视角的几何补救（#7）、NeRF 式位姿优化（#11）、合成数据（#102）与 UAV 场景（#17）；2026 年的 #8 PnLCalib、#16 TacticalCalib、#94、#14 则分别在点线联合优化、端到端位姿回归、镜头畸变与运动无关标定、免训练视角不变配准上继续推进。主要子问题为：(a) 单帧多机位 3D 标定；(b) 可见地标稀少视角的鲁棒性；(c) 视频序列中的时序一致性；(d) 评测协议、模板与数据。

代表性工作

(a) 优化式标定。 #1 TVCalib: Camera Calibration for Sports Field Registration in Soccer（2023）不做 2D–3D 关键点对应，而是把场地建模为线段/点云 segment，用可微的 segment reprojection loss 对 pinhole 参数 (FoV, t, pan, tilt, roll) 做 AdamW 迭代优化，并从 center/left/right 三组机位先验多起点初始化。在 SN-Calib-test-center（1,454 张）GT 分割输入下 AC@5/10/20 = 68.7/88.0/96.1%、CS 76.9；预测分割下 AC@5 降至 57.6%，说明分割质量是瓶颈。作者手工标注的机位类型（center 52.7%、left 10%、right 9.5%、other 28%）后来被多篇工作沿用为 SN22-test-center 子集。

(b) 关键点驱动的 3D 标定。 #5 Enhancing Soccer Camera Calibration Through Keypoint Exploitation（2024）从线标注派生 57 个结构关键点（线-线交点、线-圆锥曲线交点、切点及单应投影附加点），HRNetV2-w48 热图检测后用 OpenCV 三平面标定加投票后处理，获 SoccerNet Calibration Challenge 2023 第一（Acc@5 0.7322 / CR 0.7559 / Score 0.5535，baseline 仅 0.0833）。#2 No Bells, Just Whistles（2024）采用类似的分层关键点网格加线端点网络，并针对 SoccerNet 多视角特性设计重投影误差 + 叉积符号的候选消歧与左右消歧；SN22-test-center 上 Acc@5 75.3%、CR 97.8%，并给出完整 SN23-test（含回放/非主机位）上首个多视角基准：Acc@5 73.7% 但 CR 仅 77.5%。#8 PnLCalib（2026）在此基础上加入点-线联合非线性精化（PnL），SN22-test-center FS 由 73.8 升至 79.5，WC14 达 JaC5 85.9 / CR 100，SN23-test 上 FS 61.8 / CR 78.4，但推理 439 ms/帧。#16 TacticalCalib（2026）面向固定高位"战术相机"，用 Lanczos-STN、亚像素 offset 与 query-driven Pose-Transformer 端到端回归 6-DoF 位姿，在从 SoccerNet-2023 过滤出的 7,418 张 tactical-view 子集上 JaC5 78.2 / CR 80.7，略优于 PnLCalib（76.7 / 79.5）；但摘要指出其正文与表格数字多处不一致。

(c) 纯几何与免训练方法。 #7 Can Geometry Save Central Views（2025）针对只见中圈与中线的中场特写，利用 pole-polar 关系由椭圆与圆心投影得到消失线，把圆对应转成点/线对应；在 SoccerNet 中场子集（8,565 张）上与 PnLCalib 持平（JaC5 22.4%），价值主要在 300 张 OOD 图像的定性泛化。#14 Viewpoint-invariant soccer pitch registration（2026）以消失点、cross-ratio 与草带过渡类型构造视角不变描述子做免训练配准，在 LaSoDa 60 张四类相机图像上全自动成功率 90%、中位 E_pix 6.2 px，优于 #2 的 MV 权重（9.5 px）；作者明确因 SN-Calib 无完整 homography 且场地尺寸不标准而未在其上评测。#11 NeRF-guided Camera Optimization（2025）用 DeepLabv3+ 语义注意力增强 PixelNeRF 并联合优化位姿，加入平面约束与基于 DETR + Depth Anything V2 的球员相对位置约束，SN-Calib 测试集 JaC5 75.8 / CR 78.3，相对 BroadTrack/NBJW 提升很小（+0.5 / +0.8）。

(d) 时序与视频。 #6 BroadTrack（2025）是本方向少有的显式时序工作：pinhole + 一阶径向畸变 k1，三脚架模型（pan/tilt 轴交点固定、焦点沿光轴随变焦移动），Lucas-Kanade 光流剔除球员区域后补充点对应，上一帧参数热启动 + Jaccard 门控重初始化。在 sn-gamestate（49 段 × 750 帧）上 JaC5 56.88 / MRE 5.02 px / CR 100，对比 NBJW 37.14 / 10.28 / 93.67；消融显示 k1 贡献最大，光流与三脚架约束主要改善参数平滑性。#94 Unified Sports Field Registration with Lens Distortion Modeling（2026）用 Levenberg-Marquardt 联合估计相机参数与 k1，随机采样 5 帧共享相机位置再加软边界时序正则，无需 tracking；SN22-center GT 线段 JaC5 86.2、SN-GSR 序列 JaC5 47.8 / CR 94.0，并引入 MultiSports-Calib。#17 Semi-Static Template Matching（2025）面向 UAV 俯拍，联合估计 homography 与场地长宽，Kalman 跟踪 + 置换一致性惩罚把时序一致性误差 TCE 从 120.6 px 降到 1.4 px。

(e) 评测协议、模板与数据。 #3 A Universal Protocol to Benchmark Camera Calibration for Sports（2024）提出与相机模型无关的 JaC 指标（即 SoccerNet 挑战的 AC），重标 WC14 后显示 GT homography JaC5 仅 67.4，而含径向畸变的 Xeebra 达 92.5；在 SN-Calib 上加入畸变使 JaC2 从 40.2 升至 54.3。#12 A Generic Virtual Template（2024）与 #9（2025）以合成实验论证 FIFA 模板对 IFAB 允许的极端场地外轮廓 IoU_mask ≥ 96.3%，但新提出的分区 IoU_seg 仅 82.9–85.4%，球门区低至 70.4%。#102 SoccerSynth Field（2025）用 UE5 合成 20,000 张场地图预训练 DeepLabV3，WC14 检测精度 98.3% → 98.5%，真实数据减少时优势更明显。#10 Soccer Pitch Areas Segmentation（2023）把 SN-Calib 线标注转为 10 类场地区域掩码训练分层 U-Net，IoU 62.4%，左右侧混淆为主要误差。两篇综述 #4（2023）与 #87（2025）分别整理经典 Hough/RANSAC/KF 流程与 ML 方法的精度-速度权衡（HRNetV2-w48 约 33 ms/帧，但整体流水线难以实时）。所有 18 篇均成功读取。

对 SoccerNet-v3 的使用

实质使用其数据的有 #1、#2、#5、#8、#10、#11、#16、#94、#102 与 #6/#7（后两者用 sn-calibration/sn-gamestate 衍生集），用的全部是 SN-Calib 的场地线/圆弧/球门柱 polyline 标注及其 train/val/test 划分；#3 用其做协议实验；#4、#87、#9、#12、#14、#17 仅作背景引用，#14 甚至明确排除。没有任何一篇使用 SoccerNet-v3 的 re-ID 标注或多视角对应关系，"多视角"仅意味着"视角多样的单帧样本"。

对换视角 re-ID + 时序的可借鉴点

本方向与身份识别的方法交集很少，价值集中在几何基础设施：

  • 统一场地坐标作为跨视角先验：#1、#2、#8 开源且覆盖 SoccerNet 全部机位，可把不同视角的球员脚点投影到同一地平面，用位置一致性筛选候选或与外观度量融合；但 SN23-test 上 CR 仅 77–78%，近景/鱼眼帧不可标定，因此只能作软约束。
  • 误差量级警示：#3 显示 homography 与富模型位置可差 >1 m，#9/#12 显示球门区局部误差更大，#14 指出 SN-Calib 场地尺寸不标准——位置阈值需按区域和置信度设定。
  • 时序设计：#6 的"上一帧热启动 + 质量门控重初始化"、#94 的多帧共享参数 + 软边界正则、#17 的 Kalman 跟踪 + 顺序一致性惩罚与无标注 TCE 指标，可迁移为 tracklet 级几何一致性约束与自监督诊断。
  • 视角标签与子集构造：#1 的机位类型标注、#10 的横线斜率视角判别、#16 的按视角过滤规则、#7 的困难中场子集，可用于构造视角差异可控的 re-ID 评测分桶。
  • 其他：#11 的球员相对位置约束（formation 一致性）、#102 的多相机随机化合成数据思路。

开放问题

（1）非主机位/回放视角的标定完整率长期停留在 ~78%，而这恰是跨视角 re-ID 最需要的帧；（2）除 #6、#94、#17 外几乎全部逐帧独立，且现有评测（JaC/CR）不衡量时序一致性；（3）镜头畸变、非标准场地尺寸与左右歧义仍靠启发式处理；（4）SN-Calib 与 re-ID/跨视角对应标注来自同一数据源，却尚无工作将二者联合（例如用已标定视角三角化球员来辅助标定或身份关联，#3 仅提出设想）；（5）精度与速度难以兼顾（PnLCalib 2.3 fps），实时多机位流水线尚未出现。

数据集与基准 11 篇

概览

本方向共 11 篇，全部读取成功。它们不提出 re-ID 方法，而是提供数据、任务定义与评测协议，共同构成了 SoccerNet-v3 周边的"基准生态"。时间上呈现清晰的演进：2022 年 SoccerNet 2022 Challenges（#104）首次把 v3 的 re-ID、场地线与标定标注变成带 challenge set 的公开任务；2022–2023 年以 DeepSportradar-v1/v2（#55、#57）为代表，针对 SoccerNet 系列"只限足球、只用转播视频、无相机参数"的局限，推出篮球固定相机数据；2024 年 SoccerNet 2023 Challenges（#56）把 SoccerNet-v3 ReID 与 tracking、jersey number 三项球员理解任务纳入统一挑战赛，同时 SoccerNet-Depth（#58）用游戏引擎扩展了深度模态；2025 年出现三条新线：SoccerNet-v3D（#59）直接在 v3 的主机位+回放对上做标定与三角化，Spiideo SoccerNet SynLoc（#81）以合成运动员+真实球场背景构造世界坐标定位基准，SoccerHigh（#83）与 SGA-INTERACT（#86）分别面向视频摘要与 3D 骨架群体活动；2026 年 MUVY（#60）与 FOOTPASS（#84）把多视角来源扩展到观众手持相机，把身份标注扩展到全场 play-by-play 事件。主要子问题可归纳为四类：(a) 球员级基准（re-ID / tracking / jersey number）；(b) 几何与 3D 标注（标定、3D 球位置、深度、世界坐标定位）；(c) 多视角/多相机采集；(d) 时序事件级标注。

代表性工作

(a) 球员级基准：从跨视角单帧检索到同视角跨时刻检索

「#104 SoccerNet 2022 Challenges Results（2022）」是 v3 跨视角 re-ID 任务的首届排行榜，也是该任务最完整的公开技术记录。六个任务共 67 队 637 次提交，数据统一分为 train / valid / test / challenge，按 challenge set 排名。Re-ID（13 队 123 次提交，mAP / R-1）：Inspur 91.68 / 89.41、MGSoccer 91.48 / 89.21、MTVACV 90.11 / 87.04、gunners 89.47 / 86.42、MIG 89.44 / 86.11，官方 baseline 59.11 / 48.41。冠军 Inspur 删掉图像少于 3 张的身份、用 focal loss、ResNeSt269 + Arc/Cos-Softmax、多分辨率模型融合，并"加入测试阶段数据"做无监督域自适应；MGSoccer 用 LUPerson 自监督预训练的 MGN-CNN + TransReID-ViT 混合结构和 action-based sampler；MTVACV 用 Catastrophic Forgetting Score 从 LUPerson 中筛出近域图像做 DINO 预训练，外加可见性与重要性感知的部件特征；MIG 按 A 个 action × I 个身份 × K 张图组 batch，指出这样可以避免同一球员在不同 action 里的不同 ID 同批出现；ReBatch 把同一 action 的图像放进同一 batch，并在推理后做 gallery 排名的互斥调整。同届跟踪任务给定真值检测框、只评关联：Kalisteo 的 TrackMerger HOTA 93.64 / AssA 88.06（baseline 70.89）；标定冠军综合分 83.96（AC@5 82.38，完整率 72.61），第 2 名 L3S（即 TVCalib 作者团队）66.58。

「#56 SoccerNet 2023 Challenges Results（2024）」是本方向另一篇与 re-ID 直接相关的文献。其 Player Re-ID 任务以 SoccerNet-v3 ReID 数据集（340,993 个球员缩略图，400 场、6 大联赛）为基准，任务定义为"在某一时刻的某个 action 内跨多个相机视角检索同一球员/裁判"。冠军 UniBw Munich 的 CLIP-ReIdent 方案用 3 个 CLIP 视觉编码器 ensemble、InfoNCE 对比微调、按 action 采样的 sampler 与 per-action re-ranking，在 challenge set 上取得 mAP 93.26 / R-1 91.26，优于 2022 冠军（#104 的 Inspur）的 91.68 / 89.41（5 队 28 次提交，首届为 13 队 123 次）。Multiple Player Tracking 冠军 Kalisteo（TrackMerger v2）以"无歧义 tracklet → triplet 微调 MGN re-ID → 按 re-ID 向量合并 tracklet"取得 HOTA 75.61，远超基线 42.38（2023 起不再提供真值检测框，与 #104 的 93.64 不可比）。Jersey Number Recognition 冠军 ZZPM 准确率 92.85%，其中 J3 用 tracklet 内逐图特征作 token 送入 transformer、J5 用 video transformer 提取 tracklet 时空特征。作者自述 v3 ReID 的困难在于同队外观高度相似、每个身份样本极少、分辨率差异大。

「#55 DeepSportradar-v1（2022）」与「#57 DeepSportradar-v2（2023）」提供了与之互补的篮球基准。v1 由 Keemotion/Synergy 自动相机系统在法国 LNB Pro A 采集，ReID 数据集含 99 段 20 帧（10 FPS）短序列、18,703 张缩略图、436 个训练 ID，query 取序列第 1 帧、gallery 取第 2–20 帧；ResNet-50 交叉熵基线在 test set 上 mAP 65%、Rank-1 90%。作者明确指出该数据所有图像来自同一相机、同一视角。v2 报告 2022 挑战赛结果已饱和（Top-3 mAP 0.97–0.98，冠军同样是 CLIP-ReIdent），故把挑战集扩大到 query 618 / gallery 9505，官方基线降至 challenge 61.1 mAP；并新增 Occlusion Metric（OIR × DPR）只在断裂实例上评估分割。

(b) 几何与 3D 标注

「#59 SoccerNet-v3D（2025）」把 SoccerNet-v3 的 broadcast 主机位帧与同步回放帧组成多相机组，用 GT 场地线驱动 PnLCalib 标定，以 JaC_0.5% > 0.75 筛选出 4,297 个可标定系统，再经重投影误差与相机位移 ≥ 1 m 过滤，最终得到 4,051 帧带 3D 球位置的 SoccerNet-v3D（train 3,240 / test 811），以及基于 ISSIA 六路静态相机的 ISSIA-3D（10,544 帧）。三角化反算的优化 box 使 IoU 从 0.57 升至 0.66；单目 3D 球定位基线 YOLO_opt 在 SoccerNet-v3D-test 上 AP@0.5 0.81、MAE 4.2 m，而仅在 v3 上训练的模型迁移到 ISSIA 时 AP@0.5 仅 0.04–0.39。

「#81 Spiideo SoccerNet SynLoc（2025）」在 17 座球场（每场两台 4K 相机各覆盖半场）的无人背景上用 Blender 渲染合成运动员，共 42,504 / 6,777 / 9,309 / 11,352 张训练/验证/测试/挑战图像、1,107,009 个标注人体，附相机矩阵与畸变多项式。提出 mAP-LocSim（tau = 1 m）与 Frame Accuracy 在世界坐标评估；最优 yolox-m pose @960 取得 mAP-LocSim 79.3，而 bbox 底边中点方案仅 52.4，尽管两者图像空间 mAP-IoU 完全相同。「#58 SoccerNet-Depth（2024）」用 NBA2K22 与 eFootball 引擎抽取 12,398 对 1080p 帧/深度图（62 场足球 + 8 场篮球），zero-shot 下 Depth Anything 最好，fine-tune ZoeDepth 后场地平面与球员轮廓显著改善。

(c) 多视角与多相机采集

「#60 MUVY（2026）」收集 YouTube Creative Commons 观众手持录像，141 段、31 个事件、7 类运动、333,180 帧，每事件 2–17 段视角，附录像级 5 类方位标签（LEFT / BEHIND_LEFT / CENTER / RIGHT / BEHIND_RIGHT）与 YOLO-World 自动生成、人工校验的 208,111 条逐帧检测。纯数据集文章，无基准实验，也不含身份或帧级同步。「#86 SGA-INTERACT（2025）」用 4 台固定于球场四角的 1080p@50FPS 相机采集 95 场 3x3 篮球，重投影误差约 2 像素；其 3D 骨架流水线以 SOLIDER Re-ID + OCSORT 做单视角跟踪，再由跨视角 Re-ID 多数投票与三角化确定全局身份。其跨视角评测极具警示性：COMPOSER 用前视 2D 训练、侧视测试时 mAcc 从 47.72（3D）降至 5.29，MPGCN 从 50.46（FV 2D）降至 4.77。但该数据集只发布 3D 骨架，无 RGB。

(d) 时序事件级标注

「#84 FOOTPASS（2026）」标注 54 场全场转播共 102,992 个 on-ball 事件（8 类），每个事件附行为球员的 jersey number + team，并发布 single-player tracklets、球场坐标/速度与 13 类战术角色。TAAD+DST 以战术先验 + 750 帧长序列去噪取得 F1 67.5（TAAD 35.9、TAAD+GNN 52.1），且在行为球员无 bbox 时仍有 33.4% 召回（TAAD 仅 3.9%）。「#83 SoccerHigh（2025）」对齐 237 场全场转播与官方集锦，DINOv2 + kNN 半自动对齐 F1 0.8407，VideoMAEv2 + 60 s 分块 Transformer 基线 F1 0.3956。

对 SoccerNet-v3 的使用

真正使用 v3 数据的有三篇。#104 是 v3 数据的第一批使用者：re-ID 任务直接用 v3 的直播↔回放球员对应，pitch localization 与 camera calibration 两项任务用 v3 的场地线与球门部件标注。#56 同样以 SoccerNet-v3 ReID 数据集为 Player Re-ID 挑战数据（利用其直播+回放跨视角球员对应与 action 级分组），Camera Calibration 任务的场地线 polyline 标注也在 v3 基础上扩充。#59 使用 v3 的主机位/回放多视角系统（原始 12,764 组）、GT 场地线标注与球 bounding box 做标定、三角化与 box 优化，但未使用其球员 re-ID 标注。其余 8 篇（#55、#57、#58、#60、#81、#83、#84、#86）均只在相关工作中作为背景引用，且多数用于论证 SoccerNet 系列"只限足球、基于转播、无相机参数"的局限。

对"换视角 re-ID + 时序"的可借鉴点

  • 训练与推理设计：#56 的 CLIP 编码器 + InfoNCE 微调、按 action（同一时刻多视角组）采样、per-action re-ranking 直接针对 v3 的跨视角结构；#104 的参赛摘要补全了这条路线的其余部件——删少样本身份 + focal loss、LUPerson 级自监督预训练（含按目标域筛选预训练数据）、可见性感知的部件特征、A×I×K 的跨 action 采样以规避假负样本、gallery 排名互斥后处理、在目标集上的推理期无监督自适应；#57 观察到 CLIP 零样本即可捕捉球衣号/颜色等视角不敏感属性。
  • 时序聚合范式：#56 中 Kalisteo 的 tracklet 级 triplet 微调与合并、J3/J5 的 tracklet token 序列 transformer，以及 #84 的生产级多趟 tracking 线索清单（队伍、球衣号+名单、颜色直方图、深度特征、IoU、角色先验）与"战术/时序先验补偿外观缺失"的 DST 思路。
  • 几何约束数据：#59 为 v3 的 4,051 张回放对提供了可靠的 {K,R,t}，可把已有球员跨视角对应投影到球场坐标做几何一致性约束或难负样本挖掘；其"相机位移 ≥ 1 m"筛选提示视角过近的回放对研究价值有限。#81、#86 展示了固定标定相机下跨视角关联的流程（三角化 + 多数投票）。
  • 对照与鲁棒性基准：#55/#57 的同视角跨时刻 ReID 可用于隔离视角变化的影响；#60 提供大幅视角差的野外多视角素材（作者明确建议用于 cross-view re-ID 与多视角对比预训练），但需自行补充身份与时间对齐。
  • 评测协议：#57 的 Occlusion Metric"只在困难实例上评估"思路可迁移为按视角差分层的 re-ID 评测；#81 的 mAP-LocSim 提示在世界坐标而非图像空间评估。

开放问题

第一，v3 ReID 挑战是单帧、逐 action 的跨视角检索，而 SoccerNet-Tracking/Jersey Number 是 tracklet 级单视角，"跨视角 + 时序"尚未在同一基准中联合（#56）。第二，现有多视角数据要么无身份标注（#60、#81），要么无 RGB（#86），要么无时间维度（#59 的 SoccerNet-v3D）；带标定、带身份、带连续序列的多相机 RGB 数据仍缺失。第三，同视角篮球 ReID 已饱和（#57 mAP 0.98），而 v3 跨视角 challenge mAP 约 93（多模型集成 + 推理期自适应，#104 / #56；单模型 test 只有 85–87，见 #103），且 v3 上训练的模型跨域到 ISSIA 时严重失效（#59），域泛化与视角泛化均待解决。第四，合成数据（#58、#81）的 sim-to-real 差距仅有定性验证；#84 的身份标注依赖专有流水线不可复现，验证/测试集各仅 3 场。

视频理解、多模态与大模型 18 篇

概览

本方向共 18 篇，是语料中与 SoccerNet-v3 主题（多视角定位与 re-ID）距离最远、但增长最快的一支。时间上呈明显的三段演进：2023 年以任务与数据集定义为主，「#46 SoccerNet-Caption（2023）」提出足球密集解说任务，「#47 VARS（2023）」提出多视角犯规识别；2024–2025 年转向文本/音频模态扩充（「#50 SoccerNet-Echoes（2024）」「#53 Beyond Audio（2025）」）与大模型接入（「#48 X-VARS（2024）」「#51 SoccerAgent（2025）」「#49 MatchVision（2025）」）；2026 年则集中出现足球专用视觉基础模型（「#82 SoccerMaster（2026）」）、大模型 VQA 系统（「#101 MSUE（2026）」「#97 SportsGrounder（2026）」）、以及面向 grounding、身份对齐、情感与球员中心推理的细分工作（「#89 SoccerLens」「#99 GameSight」「#54 SCORE」「#90 BasketEvent」，均 2026）。主要子问题可归为五类：(a) 解说文本与音频资源构建；(b) 多视角犯规识别与可解释裁判；(c) 足球专用视频编码器/基础模型；(d) 解说生成与球员身份对齐；(e) 知识型 VQA、Agent 与球员中心时序推理。所有 18 篇均成功读取。

代表性工作

(a) 解说与音频文本资源。 「#46 SoccerNet-Caption（2023）」定义 single-anchored dense video captioning：在整场转播中先定位解说时间点再生成文本，发布 36,894 条带时间戳解说（471 场），并提供 original / identified（[PLAYER_uid]）/ anonymized 三版标签。基线沿用 SoccerNet-v2 预提取特征 + NetVLAD++ 聚合，解说 spotting 最佳 mAP@30 仅 44.5%、mAP@5 约 10%，captioning 最佳 CIDEr 18.2（45 s 窗口）。作者明确指出：不引入身份识别/跟踪/re-ID 模块，就几乎不可能生成带真实球员姓名的解说。「#50 SoccerNet-Echoes（2024）」用 Whisper large-v1/v2/v3 转写全部 1100 个半场的解说音频并翻译为英文，在 GOAL 的 20 场人工转写上 WER 0.443–0.551，实体名识别弱且存在幻觉。「#53 Beyond Audio（2025）」在其上验证文本模态价值：8 类事件检测中 audio-video-text 三模态 F1 0.7175 略优于 video-only 0.6943；用 LLM 从解说抽取 17 类官方事件时 Gemini-1.5-Pro 纯文本 F1 0.6730，而加入视频后反而降至 0.5291（−21%），作者归因于解说与回放画面的时间不对齐。

(b) 多视角犯规识别与可解释裁判。 「#47 VARS（2023）」是本方向唯一显式处理多视角视频的工作：发布 SoccerNet-MVFouls（3,901 个犯规动作、8,923 个片段，平均 2.29 个视角，含 live 与经裁判时间对齐的 replay），采用 E→A→C 流水线，编码器逐视角提特征后做 view-level Mean/Max 池化。MViT + Max 在犯规类型上 Acc@1 0.47，多任务训练把严重程度 Acc 从 0.29 提升到 0.43；视角消融显示 live 单视角仅 0.31，单 replay 0.47，L+R1+R2 达 0.57；时序消融表明 16 帧覆盖 1.0 s（16 FPS）最优，扩大时间窗反而下降。「#48 X-VARS（2024）」在 MVFouls 上构建 SoccerNet-XFoul（22k+ 裁判问答），以 CLIP ViT-L/14 + Vicuna 生成判罚解释，并把分类头的离散预测作为文本 token 注入 prompt；单视角微调 CLIP 即在 offence/severity 上 Acc 0.52 超过多视角 VARS 的 0.43，人类裁判盲评 3.8 分 vs 人类 4.0 分。值得注意的是它刻意只用单视角，未利用 MVFouls 的多机位信息。

(c) 足球专用视频编码器与基础模型。 「#49 Towards Universal Soccer Video Understanding（2025）」发布 SoccerReplay-1988（1,988 场、24 类事件）并提出 MatchVision：以 SigLIP 初始化空间注意力、随机初始化交替插入的 temporal attention，输出逐帧 T×D 特征。冻结编码器下事件分类 Top-1 84.0%（SigLIP 微调仅 55.9%），解说生成 CIDEr 44.18，多视角犯规识别用 Mean pooling 得 foul type 0.44 / severity 0.58。「#82 SoccerMaster（2026）」将其推进为统一的足球视觉基础模型：SigLIP 2 初始化的 ViT，前 16 层逐帧空间注意力、后 8 层 TimeSformer 式时空注意力，用四个轻量头（Deformable DETR 式运动员检测+角色+球衣号、PnLCalib 式场地关键点/线热图、事件分类、视频-解说对比对齐）做监督式多任务预训练。配套的 SoccerFactory 流水线用 YOLOv8 + StrongSORT + PRTReID 嵌入跟踪、Qwen2.5-VL 读球衣号、SAM2 纠正 ID switch、按 ReID 嵌入与球衣号一致性合并碎片 tracklet，从 SoccerNet-v2 的 500 场主摄像机片段生成 2.7M 帧伪标注，在 SoccerNet-GSR 挑战测试集上 GS-HOTA 64.1 超过冠军 KIST-GSR 的 61.5。SoccerMaster 运动员检测 mAP 49.5（最强基线 32.0）、事件分类 77.2%（MatchVision 65.3%）；接 MOTIP 头做端到端 MOT 时 HOTA 59.1 / IDF1 74.6，但 AssA 53.9 低于 YOLOv8+PRTReID 的 58.6，说明端到端关联仍弱于专门 ReID 跟踪器。「#89 SoccerLens（2026）」则反向检验这些模型：在 200 个 MatchTime 片段上标注三级视觉线索框，提出兼顾时间维的归因方法 Chefer-T，发现 SoccerMaster 准确率 66.0% 最高但空间 grounding 弱于 MatchVision，且所有模型 grounding 不超过 50%，无时序注意力的 SigLIP T-IoU（约 19%）反而优于两者（约 15%）。

(d) 解说生成与球员身份对齐。 「#96 Dense soccer video captioning（2026）」用 perceiver resampler 融合小时级全局特征与局部特征，并用 sn-gamestate 提取球员绝对场地坐标（HashGrid 编码）作为空间特征，相比 Delta 在 CIDEr@30 上提升 16.81。「#99 GameSight（2026）」把匿名解说中的 [PLAYER]/[TEAM] 对齐到具体实体：Stage I 用 Video-LMM（SFT + GRPO）结合镜头边界/视角分类、人脸识别、球衣识别、球队归属检测和迭代更新的比赛状态做实体对齐，球员对齐准确率比 Gemini 2.5-pro 高 18.5%；Stage II 用 SoccerKAG 引入外部统计，知识引用准确率 64.60→81.80。人类专家 Player Guessing 准确率 96.3%，其中 84.5% 依赖长镜头跟踪以外的线索（特写、中景切换）。「#85 Live football commentary system（2025）」以 SoccerNet-GSR 跟踪工具 + 球衣号 OCR 识别球员并通过 RAG 生成背景信息，人工评测中用 SoccerNet-v3 ground-truth 球员列表替换识别模块后得分从 1.95 升至 2.11，直接说明身份识别是瓶颈（所用跟踪基线 GS-HOTA 仅 22.26%）。「#92 TGLG（2025）」用 SoccerNet 解说音频构建流式生成基准，VLM-TSI 通过视觉/文本 token 时间交错在 TRACE 上 38.3 vs 26.5。

(e) 知识型 VQA、Agent 与球员中心推理。 「#51 SoccerAgent（2025）」构建 SoccerWiki 与 13 任务 SoccerBench，用 DeepSeek-v3 规划/执行 18 个工具，TextQA 85.0 / ImageQA 73.3 / VideoQA 60.9 优于 GPT-4o（61.6 / 62.3 / 57.5）；但人脸识别工具准确率仅 63.4%，Replay Grounding 35.7 与 Multi-view Foul 55.5 弱于通用 VLM。「#101 MSUE（2026）」为 2026 SoccerNet VQA Challenge 技术报告，Qwen3-VL-32B 两阶段微调 + 三专家路由，测试集 accuracy 0.91（摘要另称 0.95，内部不一致）。「#97 SportsGrounder（2026）」用 OV-DINO proposal 逐帧交错注入 LMM，SoccerNet 派生 VQA 上 Overall 51.8%，但 Jersey Number 子任务仅 33.4%。「#54 SCORE（2026）」在 2 s 片段上做序数情感识别，以 32 个可学习 query 压缩视觉 token，并用证据校准的偏好优化把 ECE 从 0.112 降到 0.065。「#52 Multi-Modal Soccer Scene Analysis（2026）」用 Temporal/Social Set Attention 交替的 coarse→fine 编码器，从球员轨迹 + crop 外观推断球轨迹与持球者，CropDrop（按球员整段序列掩码外观）使 ADE 从 1.7179 m 降到 1.1735 m，持球者准确率 89.56%；数据为 Kognia 专有。「#90 BasketEvent（2026）」在 NBA 转播上做 who/what/when 联合推理，PlayNet 把 F1 从 0.46 提升到 0.68。

对 SoccerNet-v3 的使用

本方向对 SoccerNet-v3 的使用极为浅层。18 篇中 14 篇仅作背景引用（列举 SoccerNet 系列任务或以 [Cioppa et al. 2022] 代指整个 SoccerNet），未触及其多视角回放帧、跨视角对应、re-ID 划分或场地线标注。有实质使用的仅 4 篇且都不涉及 re-ID 协议：「#51」以"SoccerNet-JN"名义使用其球员裁剪图 + 球衣号标签生成 200 条 QA；「#85」在人工评测中把 v3 的 ground-truth 球员列表作为识别模块上界；「#92」以 v3 作为 SoccerNet 视频与解说音频的引用来源；「#101」把 v3 素材转成 caption/MCQ 训练样本。「#47」在数据集对比表中列出 v3 的 33,986 张 re-ID 图像以强调自身为"多视角视频"。尤其值得注意的是「#82」的 SoccerFactory 明确剔除 replay、特写和其他机位，只处理主摄像机片段——本方向最强的模型恰恰主动回避了 v3 的多视角设定。

对"换视角 re-ID + 时序"的可借鉴点

本方向与读者主题交集有限，但有四类可直接迁移的内容：

  • 多视角视频素材：「#47」的 SoccerNet-MVFouls 提供同一事件、经裁判逐视角时间对齐的 live + replay 片段，是 v3 多视角静态帧的"视频版"，可用于构造跨视角同步 tracklet 对（无身份标注，需自行关联）。「#47」的经验也直接适用：远景 live 单视角信息量远低于近景 replay（0.31 vs 0.47），Max 池化在视角质量不均时略优于 Mean，为跨视角匹配中的视角质量加权提供依据。
  • 序列特征聚合骨架：「#49」「#82」的"图像 VLM 权重初始化空间注意力 + 随机初始化交替 temporal attention"配方，「#52」的 Temporal Set Attention（agent 内沿时间）与 Social Set Attention（帧内跨 agent）交替结构，「#54」的可学习 query 瓶颈，均可作为 tracklet 级外观序列聚合的候选设计。「#52」的 CropDrop（整段序列掩码外观、强制依赖轨迹/上下文，且优于随机帧掩码）是训练在换视角导致外观不可靠时仍能关联身份的现成正则化技巧。「#82」的 MOTIP 头（历史轨迹作为 in-context identity prompt、ID 预测当作分类）与 DETR 目标级特征也可作为身份关联模块参考。
  • 多线索身份整合：「#82」SoccerFactory 的"ReID 嵌入 + 球衣号 + 场地坐标聚类"tracklet 级身份合并、「#99」融合镜头切换、人脸、球衣与比赛状态的实体对齐，都是把外观匹配与视角不变线索（相机标定后的球场坐标、球衣号）结合的实例，可直接迁移到跨视角球员关联。
  • 弱监督与评测：「#46」identified 版解说与「#50」「#53」带时间戳、含球员名的解说文本与 v3 同源（同一批 SoccerNet 比赛），可作为弱身份信号，但需按「#50」所述清洗实体名错误。「#54」按 shot scale / 遮挡 / home-away 分层报告性能的协议、「#89」的时序归因（Chefer-T）可用于检验时序 re-ID 模型是否真正利用时间信息。

开放问题

其一，身份识别是整个方向公认的瓶颈却尚无人正面解决：「#46」将其列为生成真名解说的前提，「#85」证明替换为 GT 身份即可显著提升，「#51」「#97」显示 LLM/Agent 的人脸和球衣号工具准确率仅 63.4% 与 33.4%，而「#82」端到端关联的 AssA 仍落后专门 ReID 跟踪器。其二，多视角在本方向被系统性简化：「#47」「#49」只做 Mean/Max 池化，「#48」直接放弃多视角，「#82」主动剔除非主机位画面，「#101」把多视角交给 VLM 处理，缺乏显式的跨视角对应建模。其三，时序建模的有效性存疑：「#89」发现专用时序训练反而损害时序 grounding，「#47」发现扩大时间窗有害，「#53」发现加视频后 LLM 抽取反而变差且归因于回放画面的时间错位。其四，评测可靠性：「#89」「#85」「#48」评测规模小，「#101」报告内部数字矛盾，「#52」依赖不公开数据集，「#82」的 2.7M 帧伪标注仅通过 GSR 测试集间接验证。这些问题恰好指向一个空缺：以 SoccerNet-v3 的多视角对应和 re-ID 标注为锚，为大模型时代的足球理解补上"跨视角、跨时间的球员身份一致性"这一环。

动作检测与动作识别 10 篇

概览

本方向在语料中共 10 篇，时间跨度 2023–2026 年，是引用 SoccerNet-v3 的文献里与 re-ID 关系最疏远的一类：它们关心的是"何时发生了什么事件"，而不是"这个人是谁"。按粒度可分为三个子问题：（a）未剪辑广播视频上的 action spotting（用单一时间戳定位 SoccerNet 17 类事件），语料中的工作不再追求新的 spotting 模型，而是转向数据效率（主动学习）、跨域迁移评测与工程标准化；（b）群体活动 / 比赛状态识别（group activity recognition, GAR），以球员集合的空间-交互结构为输入，从 2024 年的因子图方法发展到 2026 年"像素 vs 位置"的模态基准；（c）单球员细粒度动作与关键事件定位，包括足球集锦中的过人/射门风格分类、持球动作可行性研究，以及高尔夫挥杆关键帧 spotting。时间演进上，2023 年的工作（#38、#41）仍以模型或框架为中心；2024 年出现明显的"基准与分析"转向（#40、#42、#45）；2025–2026 年则以多模态/轨迹输入的群体识别（#44、#88）和实时部署（#43）为主。

代表性工作

2.1 Action spotting：数据效率、迁移与工具

「#105 Deep Learning for Action Spotting in Association Football Videos（2025，书章）」是这一子方向的综述性材料，可以当作下面三篇的背景。它把任务形式化为"用单个时间戳定位事件"，梳理了数据沿革（SoccerNet-v1 3 类 6,637 个事件 → v2 17 类 110,458 个事件 → Ball Action Spotting 2023 的 2 类 11,041 个时间戳 → 2024 的 12 类），用 backbone–neck–head 框架（与 #42 一致）把方法分为基于预提特征（NetVLAD++、CALF、百度多骨干特征 + transformer）与端到端（E2E-Spot 的 RegNet-Y + GSM + GRU、Baikulov 的灰度帧堆叠、T-DEED）两类，并汇总了 loose / tight a-mAP 与 mAP@1 下的历届排行榜：SoccerNet-v2 challenge tight a-mAP 最高 71.31（MEDet），COMEDIAN 在 test 上 73.1；Ball Action Spotting 2023 冠军 mAP@1 86.47，2024 冠军 T-DEED 73.39。无新实验。

「#38 Towards Active Learning for Action Spotting in Association Football Videos（2023）」提出首个面向 action spotting 的主动学习框架：在已标注集上训练 spotting 模型，用不确定性选择函数对未标注 clip 池打分，取 top-k 交给 oracle 标注后迭代。两种选择器分别是仅用最高类置信度的 Uncertainty Measure（UM）和需要完整类别分布的 Entropy Measure（EM）；对逐帧输出的 PTS 模型先按帧打分再 max/mean pooling 成 clip 级分数。基线为 NetVLAD++（冻结 ResNet152 特征）与 PTS（ResNet18 + GRU 端到端）。在 SoccerNet-v2 + NetVLAD++ 上，EM 的 AULC 为 47.96，高于 UM 46.24 和随机采样 45.11；达到最终性能 90% 所需数据比例 EM 仅 16%，随机采样需 45%；只用 5% 数据时 loose Avg-mAP EM 37.24 vs 随机 32.06。加速版调度（LR 1e-2→1e-4、patience 5）训练时间减半而性能持平。作者也承认结果并非全面一致：PTS 在 SoccerNet-ball 上 mean-EM（54.26）反而低于随机采样（56.37）。

「#40 Beyond the Premier: Assessing Action Spotting Transfer Capability Across Diverse Domains（2024）」是纯分析论文，把"转播形态"当作显式域变量：在 SoccerNet 六大联赛剪辑转播上训练，零样本迁移到瑞士 Super League 单机位人工主镜头（复用 SoccerNet-Tracking 的 9 场视频并新增 2,387 个事件标注）、卢森堡 BGL 半职业联赛 AI 导播摄像机（165 事件）和西班牙业余联赛 Cinfo AI 导播摄像机（164 事件）。关键发现：端到端模型迁移到主镜头几乎无损（E2E-Spot rny008 tight-AmAP 61.82→70.02；COMEDIAN ViSwin-Tiny 71.60→72.39），但到 AI 导播域大幅下降（E2E-Spot 到 BGL 24.09、到 CINFO 19.56；COMEDIAN 41.31 / 25.93）；特征型方法则崩溃式退化（CALF 14.10→0.74/0.37，NetVLAD++ 11.51→2.21/1.10）。作者据此总结：冻结特征 + 池化的方法 tight-AmAP 在新域最高仅 5.08%，而端到端方法在所有域都不低于 18.89%；ensemble 在源域最好但迁移反而不如单模型。局限是新域测试集各仅 1 场比赛，且未分离"联赛水平"与"相机质量"两个混杂因素。

「#42 OSL-ActionSpotting: A Unified Library for Action Spotting in Sports Videos（2024）」是工程贡献：把任意 spotting 算法抽象为 Backbone → Neck → Head 三段，集成时序感知池化（NetVLAD++ 等）、CALF 和端到端 PTS，提供 feature-based 与 video-based（OpenCV / NVIDIA DALI）两种加载器和 COCO 式 JSON 数据格式。SoccerNet-v2 上复现结果：NetVLAD++ loose/tight 51.5/8.1，CALF 39.5/12.4，PTS(RNY008) 72.2/66.2；但 PTS 训练需 249,780 s 与 4 张 GPU，其余方法在单张 RTX1080 上即可完成。这与 #40 的结论互为印证：端到端时空特征在 tight 指标上有数量级优势，代价是算力。

2.2 群体活动与比赛状态识别

「#39 Active Factor Graph Network for Group Activity Recognition（2024）」认为只建模两两交互不够，且噪声个体会误导群体预测，因此提出 AFGNet：先用交互检测器预测两两交互权重，按个体影响力 inf_i = Σ_j e_ij 取 top-k 作为"主动个体"，再为每个三元组建因子节点建模三阶交互（堆叠 10 层因子图神经网络），并以 Full Factor Graph 与 Active Factor Graph 双分支融合。Volleyball 上 Group/Individual 准确率 96.7%/86.1%，CAD 96.5%，CAE 96.9%。本文是语料中唯一真正把 SoccerNet-v3 当作评测集的工作（详见第 3 节）：在 33,986 帧、16 类事件标签上，Baseline 66.4% → +ARG 70.1% → +FGC 71.2% → +AFGC（9 个主动个体）75.0%，但只与自身基线比较，且单帧输入、去掉了 LSTM 与一致性推理模块。

「#88 Pixels or Positions? Benchmarking Modalities in Group Activity Recognition（2026）」构建 SoccerNet-GAR 多模态基准：来自 PFF FC 提供的 2022 世界杯 64 场比赛，广播视频与 30 fps 球员/球轨迹按 UTC 时间戳对齐，87,939 个事件、10 类，每个事件取 4.5 s 窗口、T=16 帧，按比赛划分 45/9/10 场。在统一的 backbone–neck–head 协议下比较视频分类器（VideoMAE/VideoMAEv2）与作者提出的 role-aware 图分类器（23 节点、8 维节点特征、20 层 GIN、MaxPool 时序聚合，按 GK/DEF/MID/FWD 战术线定义边）。结果：跟踪模型 77.8% balanced accuracy / 57.0% macro F1（180K 参数，约 4 GPU 小时），最佳视频模型 60.9% / 50.1%（86.3M 参数，28 GPU 小时），跟踪高出 16.9 pp，参数少 479 倍；10 类中 9 类跟踪占优，GOAL 类 73.3% vs 16.7%。消融显示 Positional 边（77.8%）显著优于全连接（71.4%）、无边（68.9%）以及距离/KNN 邻接（66.7–68.6%），即几何近邻边几乎无收益；时序聚合上 MaxPool balanced accuracy 最高（77.8%），但 TCN/Attention/BiLSTM 的 macro F1 更高（58.4/58.3/57.9 vs 57.0）。局限是类别极度不平衡（PASS 占 65.4%，GOAL 仅 30 个测试样本），视频模型单次运行，且轨迹为人工精修的"干净"输入。

「#43 Real-time analysis of indoor sports game situations through deep learning-based classification（2026）」面向手球/篮球无人值守直播，将每帧分为 7 类比赛状态。流水线为 YOLOv4 检测 → 最近邻短时关联求速度向量 → 每相机 4-point 单应变换到统一鸟瞰空间 → 生成 224×224 合成帧 → 自定义 densenet23 分类。在 Play by Play 数据集（20 场手球 + 2 场篮球）上，densenet23（480K 参数）手球 Accuracy 0.986 / F1 macro 0.961，篮球 0.972 / 0.925；去掉速度向量后 F1 macro 分别下降 8.8 与 13.7 个百分点；整条流水线 GPU 时延 34.04 ms，其中 YOLOv4 占 88%。论文明确声明不需要长期 re-identification。

2.3 单球员细粒度动作与关键事件

「#41 Energy-Motion Features Aggregation Network for Players' Fine-Grained Action Analysis in Soccer Videos（2023）」区分过人（Stepover/Elastico/Chop）与射门（Penalty/Goal/Free-Kick）六种细粒度风格。核心是以左髋、右髋、左肩构成的三角形求仿射变换，把每帧球员分割 mask 对齐到参考帧并累积成单张 energy image 以消除相机运动，再用共享 ViT 分别提取 energy 特征与逐帧特征，后者经 6 层 transformer 得到运动特征，最后异源聚合。射门三分类 A-F1 0.931（Video Swin 0.68），过人三分类 0.767，六类混合 0.794；消融表明仅 energy 特征 0.788、仅 motion 特征 0.424，两者聚合最优。目标球员跨帧关联仅靠 IoU 阈值，无外观匹配。

「#45 Toward Soccer Player On-the-ball Action Recognition from Broadcast Match Videos: Data Collection, Analysis and Findings（2024）」是可行性研究：设想"姿态估计 + 球员/球检测跟踪"识别 Dribble/Pass/Shoot，人工从比赛视频中在触球瞬间截取 3,018 帧（每类 1,006 帧，Shoot 类需 40 场比赛才凑齐）。定性结论是 HRNet 在低分辨率球员上优于 OpenPose 与 MediaPipe；球检测方面 YOLOv5/DeepSORT 触球瞬间 TP 仅约 10–25%，Shoot 类 FP:TP 约 2:1，FootAndBall 几乎完全失效。完整识别系统未实现，亦无动作分类指标。

「#44 Frame-Skeleton: A Dual-Stream Network for Action Events Sequence Spotting（2025）」针对高尔夫挥杆逐帧定位 8/10 个关键事件：RGB 流用 MobileNetV2，骨架流用 TCN 步幅固定为 1 的改进 ST-GCN 以保留逐帧分辨率，投影相加后经 MLP 通道注意力融合，再由两层 Bi-LSTM 建模长程依赖。Golfdb 上平均 PCE 77.4（R(2+1)D 77.2，SwingNet 71.5），参数 8.17M 不到 R3D 的三分之一；自建 Frameflow（205 段，含 50 段非职业）上 71.6 vs T-DEED 68.9；双流对非职业球员提升最明显（57.3→74.1）。

对 SoccerNet-v3 的使用

10 篇中仅 2 篇真正使用了 SoccerNet-v3 的数据，且都没有触及其核心的多视角 / re-ID 标注：

  • #39 将 SoccerNet-v3 的 33,986 帧（400 场）视为独立单帧样本，划分为 25,311 / 3,945 / 4,730，用帧级 16 类事件标签（Goal、Corner、Yellow card 等）作为"群体活动"标签，并用帧内球员 bounding box 做 RoIAlign。re-ID 身份、回放帧之间的对应关系、场地线标定均未使用，多视角回放帧被当作互不相关的单视角图片。
  • #45 仅把 SoccerNet-v3 当作原始比赛视频来源（1280×720、25 fps），自行标注 on-the-ball 动作帧；其"SoccerNet-v3 = 500 场完整视频"的说法实际指 SoccerNet 视频语料本身。

其余 8 篇（#38、#40、#41、#42、#43、#44、#88、#105）均只在 Related Work 或数据集沿革中把 SoccerNet-v3 作为 SoccerNet 系列的扩展一句带过（多数提及 camera calibration / re-identification / cross-view correspondences），实验数据来自 SoccerNet-v2、SoccerNet-Tracking、PFF FC 世界杯数据或自建数据集。值得注意的是 #88 虽命名为 SoccerNet-GAR 且作者与 SoccerNet 团队重叠，其数据源与 SoccerNet-v3 完全无关。

对"换视角 re-ID + 时序"的可借鉴点

本方向与读者方向交集很少：10 篇均无身份匹配模块，reid 相关度最高仅 1 分（#45，且是对球而非球员的遮挡后重识别）；crossview 最高 1 分（#40、#43），且本质是相机风格 / 多相机几何对齐而非同步多视角匹配。可迁移的内容集中在三个层面：

时序聚合设计选型。 #88 的消融是最直接的参考：对 4.5 s、16 帧的短窗口，MaxPool 在 balanced accuracy 上不逊于 Attention/TCN/BiLSTM，而可学习模块在 macro F1 上略优——这对 tracklet 级特征聚合"是否值得引入可学习时序模块"给出了一组可对照的数字。#44 的"短时卷积（stride=1 的 TCN）保留逐帧分辨率 + Bi-LSTM 承担长程依赖"的分工，以及 #41 的"配准后静态 energy 表示与 transformer 时序特征异源聚合"（motion-only 0.424 vs energy-only 0.788 vs 聚合最优），都提示纯时序特征需与静态表示互补。#42 库内的 NetVLAD++、GRU 头、CALF 是现成的序列聚合实现。

结构先验与跨相机几何。 #88 表明用领域先验（战术角色）定义图连接显著优于几何近邻边（+6.4 pp 对全连接、+8.9 pp 对无边），启发在球员 re-ID 中把队伍/角色/阵型位置作为图约束或匹配先验；#39 的"交互权重 → 个体影响力 → top-k 剪枝"是轻量的关键人物选择机制，其三阶因子图可启发跨视角分配的高阶一致性约束。#43 的每相机 4-point 单应到鸟瞰坐标，是与 SoccerNet-v3 场地线标定同类的跨相机空间先验，可用于候选剪枝。

评测范式与数据效率。 #40 的 train-on-one-domain / test-on-all 矩阵式评测，可直接搬用于量化跨视角 re-ID 在不同相机类型（剪辑转播 / 固定主镜头 / AI 导播）下的鲁棒性；其"端到端微调的时序模型远比冻结特征 + 池化抗域漂移"的结论对 backbone 选择有参考价值。#38 的不确定性采样、逐帧打分 max pooling 到序列级、以及 AULC / M%data / M%perf 指标，可迁移到 tracklet 或跨视角匹配对的主动标注中。#44 按球员划分数据集以防风格泄漏，与 re-ID 按身份划分的原则一致。

数据资源。 #40 为 SoccerNet-Tracking 的瑞士 Super League 主镜头视频新增了 action spotting 标签，可与其 tracking/re-ID 标注联合做事件驱动的身份关联实验；#39 给出了把 SoccerNet-v3 改造成帧级事件分类基准的划分方案，可用于按事件类型分析跨视角匹配难度；#88 的 SoccerNet-GAR 提供广播视频与球场坐标轨迹（含角色元数据）的同步数据，但不含多相机视角或身份标注。

开放问题

  • 模态与输入质量。 #88 证明干净轨迹远优于像素，但真实自动跟踪输出（含身份切换）下的差距未评估；从像素到位置的桥梁正是检测-跟踪-re-ID 流水线，本方向对其误差传播基本未涉及（#43 检测占 88% 时延且是主要错误源，#45 球检测 TP 仅 10–25%）。
  • 跨域鲁棒性。 #40 显示 AI 导播域 tight-AmAP 骤降，但仅做零样本评测，未尝试 domain adaptation，也未分离联赛水平与相机质量两个因素；新域测试集各仅 1 场比赛。
  • 时序因果与在线性。 #88 以事件时刻为中心的窗口用到未来帧，#43 只用单帧合成表示并自述需引入多帧时序；实时、因果的动作/状态识别仍待解决。
  • 稀有类与小样本。 #88 GOAL 仅 30 个测试样本、#41 Free-Kick 仅 39 clips、#45 Shoot 类需 40 场才凑齐，长尾事件的可靠评测尚无共识；#38 的主动学习只探索了不确定性采样一类策略。
  • SoccerNet-v3 多视角标注的闲置。 语料中无任何工作利用其回放帧对应关系做跨视角动作识别，#39 甚至把多视角帧当作独立样本——"同一事件的多视角一致性"在动作识别中完全未被开发，这恰是与读者方向最可能产生交集的空白。

综述、体育科学应用与跨领域引用 19 篇

概览

本方向共 19 篇，是语料中与换视角 re-ID 技术关系最疏离、但最能反映 SoccerNet-v3 生态影响力的一组。按性质可分三类：（a）体育视频理解综述 7 篇（#63、#64、#65、#66、#67、#69、#100），时间上从 2023 年的 arXiv 综述（#64、#69）演进到 2024–2025 年的期刊综述与教材章节（#63、#65、#66、#67），再到 2025–2026 年面向解说生成等新兴任务的综述（#100）；（b）体育科学/工程应用 8 篇（#70、#71、#72、#73、#74、#76、#77、#91），集中于 2024–2026 年，多为利用转播视频或多相机系统做运动学、判罚辅助、内容生成的下游研究，其中 #71、#91 已扩展到 2026 年的 xG 建模与疲劳评估；（c）跨领域引用 4 篇（#62 医疗 CV、#68 文献计量、#75 运动医学、#78 区域经济学），SoccerNet-v3 在其中只是"AI 与体育共享数据"的例证。主要子问题包括：体育 CV 任务分类学、从视频导出运动学指标、多视角系统的同步与标定、以及 re-ID 在综述中的定位。所有 19 篇均成功读取（mode=light）。

代表性工作

（a）体育视频理解综述。 「#67 Computer Vision for Sports Analytics（2025）」是本组对 re-ID 描述最直接的一篇：作为教材章节，它按 field registration、tracking、re-identification、action recognition、pose estimation 分节，并在 Re-ID 小节区分 image-level、tracklet-level（更贴近实际）与 open-world 三种设置，指出 SoccerNet GSR 结合 role、team、jersey number 做 video-level re-ID 优于纯 image-level；列出的 SoccerNet Re-ID 数据集含 340,993 张球员 thumbnails、400 场比赛。「#64 A Survey of Deep Learning in Sports Applications（2023）」提出 Perception / Comprehension / Decision 三层分类法，在 Perception 层设 Player Re-ID 小节，明确 re-ID 是"跨时间与不同视角匹配个体"，罗列 jersey number 识别、Siamese/triplet loss、多粒度注意力、CLIP+InfoNCE 及基于 replay frame 排序的 re-ID 等路线，但未做性能比较。「#66 How AI-based computer vision algorithms are impacting the sports industry（2025）」以 physical understanding（calibration/detection/tracking）与 logical understanding（event spotting/relationship/performance）两级组织，将 deep-feature appearance / ReID embeddings 列为 tracking 的一个方法类别，并归纳 lack of temporal consistency、requires multi-view 等局限。「#63 A survey of video-based human action recognition in team sports（2024）」聚焦 HAR 三个子任务，把广播视频 viewpoint change 导致的球员/球 tracking 断裂列为开放挑战，并在数据集章节写明 SoccerNet-v3 是 multi-view spatial localisation 与 re-ID 数据集。「#65 A Review of Computer Vision Technology for Football Videos（2025）」以 PRISMA 流程从 217 篇筛至 49 篇，转述 SoccerNet_v3_H250 子集（14,368/2,726/2,692 图像）上 FootAndBall 球召回从 2% 提升至 68% 的结果。「#69 Survey of Action Recognition, Spotting, and Spatio-Temporal Localization in Soccer（2023）」给出 SoccerNet-v3 标注统计（replay 帧 21,222、球员/裁判 bbox 344,660、multi-view correspondences 172,622、jersey numbers 106,592）。「#100 From Multimodal Perception to Strategic Reasoning（2025）」面向 AI 解说生成，仅一句话提及 SoccerNet-v3 增加了 spatial annotations。

（b）体育科学/工程应用。 这些工作大多以 SoccerNet 视频或 SoccerNet-GSR 为输入，做面向事件或运动学的时序分析。「#70 Foul prediction with estimated poses from soccer broadcast video（2024）」用 SoccerNet-v3 的 foul 等标签时间戳截取 2,500 fouls / 2,500 non-fouls 片段，ByteTrack 跟踪 + OCHuman 姿态，CNN+GRU 融合 video/bbox/pose 四模态，Acc 77.4%（仅 video 的 CNN 为 65.4%）；有趣的是帧数从 4 增至 45 无提升，64×64 全局图像最佳。「#91 Towards Athlete Fatigue Assessment from Association Football Videos（2026）」用单目 GSR 方法 Broadcast2Pitch 得到轨迹（746 条中 578 条与 GT 匹配），经 Kalman/Savitzky–Golay 平滑与中心差分得速度/加速度，构建 A–S profile，45 分钟半场后半段拟合斜率 −0.701 与疲劳效应一致。「#72 Extracting Player Speed from Football Videos（2025）」比较 YOLOv8/v11 × Deep-EIoU/StrongSORT × PnLCalib × homography 四种配置，最佳在 SoccerNet-GSR 上相对误差 27.3%、RMSE 1.60 m/s，冲刺段降至 14.4%，远逊于商用 TRACAB 的约 2%。「#71 Once Upon a Goal（2026）」构建 xGHub（704 场，视频源含 SoccerNet），BoT-SORT + PnLCalib + ViTPose/HMR2.0 + PHALP 抽取 3D 朝向特征，XGBoost 加入 3D orientation 后 AUROC 0.7881（基线 0.7868），增益小但能区分极端朝向情境。「#74 Semi-automated last touch detection（2025）」基于 Hawk-Eye 29 关节骨架与智能球数据做出界球权判定，触球概率模型 AUC 0.97，Volumetric Closeness Approach 准确率 82.1%。「#76 An End-To-End Pipeline for Virtual Banner Replacement（2025）」提出 SoccerNet-Banner 数据集，Mask2Former 分割 + NBJW 标定 + 三级时序滤波，标定 completeness 从 93.65% 升至 100%。「#73 Breaking the Game（2025）」用 8 台 4K 相机做篮球 3D 姿态三角化，内参重投影误差 1.01–3.52 px。「#77 Investigating Event-Based Cameras for Video Frame Interpolation（2024）」用 RGB+事件相机与 TimeLens 生成慢动作，仅定性结果。

（c）跨领域引用。 「#68 Uncovering data-driven Football（2026）」对 152 篇足球分析文献做 LDA 得到 7 个主题，称 SoccerNet-v3 为最大多视角足球数据集（1,324,732 标注 / 33,986 图像）。「#75 Artificial intelligence for motion analysis（2025）」面向骨科读者，把 re-identification 与 multi-view 同步/标定列为团队运动运动分析瓶颈。「#62 Applied Artificial Intelligence in Healthcare（2024）」与「#78 Coupling coordination between AI and the sports industry（2026）」分别为医疗 CV 综述与省级面板计量研究，仅在表格或理论框架中顺带引用。

对 SoccerNet-v3 的使用方式

真正接触 SoccerNet-v3 数据的只有 #70（使用其 action 时间戳裁剪视频片段）和 #71（作为转播视频与事件时间戳来源），二者均未触及多视角对应或 re-ID 标注。#72、#76、#91 实验用的是 SoccerNet-GSR，#72 和 #66 把 v3 当作 camera calibration 基准（SN-Calib）引用；#73 将其概念性地引为 cross-view temporal refinement。其余综述（#63、#64、#67、#69、#68）在数据集章节转述其规模与多视角 re-ID 属性，#62、#75、#77、#78、#100 只是列表式引用。

对换视角 re-ID + 时序方向的可借鉴点

本方向与读者方向交集很少，但有三点值得记录：其一，#67 提出的 image-level / tracklet-level / open-world 三级设置及 GSR 的 video-level re-ID（融合 role、team、jersey number）可作为综述中定义"时序 re-ID"评测层级的参照；#64 对体育 re-ID 方法路线的罗列可作入门索引。其二，#63、#66、#75 从不同角度把"广播视角切换导致跟踪断裂""lack of temporal consistency""遮挡后保持身份"列为开放挑战，可用作动机性引用。其三，应用型工作展示了序列级平滑的通用技巧——#76 的插值+中值+Savitzky–Golay 三级滤波、#91 的 Kalman 平滑与窗口差分、#71 用 PHALP 借时序恢复遮挡下的 3D mesh——以及 #70 的"时间戳裁剪 + ByteTrack + 姿态"序列特征构建流程，可迁移到 tracklet 级 re-ID 的特征稳定化。

开放问题

（1）现有综述对 re-ID 的覆盖停留在方法罗列，缺乏跨视角不变性设计与时序聚合策略的定量比较（#64、#66、#67 均自述此局限）。（2）应用研究普遍依赖单目转播视频与现成跟踪器，身份关联仅靠 StrongSORT/BoT-SORT 或人工指定目标球员（#71、#72），跟踪断裂直接导致下游指标缺失，说明鲁棒的跨镜头身份维持是体育科学落地的前置瓶颈。（3）多视角系统（#73、#75）的同步、标定与 cross-view correspondence 仍靠人工工具检视，缺乏与 SoccerNet-v3 多视角标注的对接。（4）综述文献存在截止时间偏早（#64、#69 止于 2022–2023）与文本截断（#63、#66）的问题，对 2024 年后 transformer/foundation model 驱动的进展覆盖不足。

5. 研究空白与可切入方向

5.1 从语料直接得出的结论（A 类，每条注明依据）

  1. 跨视角球员 re-ID 是一个被数据集"提出"但没被方法论文"接住"的问题。 SoccerNet-v3（#79）提供了 172,622 条直播↔回放对应，但把它当作 benchmark 的只有两届挑战赛（#104、#56）和一篇方法论文（#103：单帧、通用 re-ID 骨干的改进，对视角差异没有任何设计，作者自己把 perspective difference 留作未来工作）；#30 明确拒绝使用它，#82 主动剔除回放与其他机位画面，标定方向凡用到 v3 数据的 12 篇全部只用其场地线（其余 6 篇仅背景引用）。
  2. 序列信息对外观模糊场景的收益是可量化的，且在这两篇里大于其它任一消融项。 #31 的 tracklet 长度曲线（Rank-1 38.51 → 69.88，n=1 → 7）、#80 的关键帧过滤（约 +38 点）、#95 的 45–51 s 均值池化（CSIS 0.716）三者一致；但 #33、#32、#88 三处非受控对比显示简单均值/投票是很强的基线，而 #56 号码冠军用的是 tracklet transformer——任何时序模块都必须与同骨干、同数据的 mean-pooling 对照。
  3. 视角不变的身份线索已经被反复验证，只是没在跨视角设定下组合过。 球衣号（#32/#35，tracklet 级 test 87–88；#80 为 68.53 / 73.77）、球场坐标（#20/#23/#28/#82；#20 的 oracle 消融显示球衣号与 pitch 定位才是 GSR 瓶颈、ReID 不是）、球队/角色（#30 的 team triplet）、阵容/时间约束（#95 MisID 0.208 → 0.174）。#28 表明属性识别器（CLIP 或 VLM）替换 OCR 组合是 GSR 的主要增量（18.11 → 60.13 / 61.48），但视角无关性未被验证——#29 的号码识别跨项目掉了 15 个点。
  4. 外观表征对视角变化没有任何显式不变性设计。 PRTreID（#30）的部位可见性门控只处理"部位缺失"，不处理同一部位跨视角的外观差异；#86 用 2D 骨架的实验表明视角敏感性可以让性能从 50 跌到 5。
  5. 几何基础设施已经够用但有 22% 的洞。 #59 为 v3 的 4,051 张多视角帧算好了 {K,R,t}；但 #2/#8 在含回放的 SN23-test 上完整率只有 77–78%，近景/鱼眼回放标不出来。
  6. 弱线索的融合方式决定成败。 #95 把号码放在硬级联第一阶段反而降低 CSIS（0.716 → 0.709）；#28 把 ReID 距离降为合并的必要条件而让语义属性主导，IDF1 +12.5。
  7. 目标域少量自适应收益极大且很快饱和。 #95：每身份 60 s 轨迹微调即把 CSIS 从 0.531 提到 0.704；#56 跟踪冠军以 tracklet 为单位微调 re-ID 后 HOTA 75.61（基线 42.38）；#20 补充材料把 GSR 基线（AssA 49.42）与采用 test-time fine-tuning ReID 的 2023 跟踪冠军（73.42）并列，是跨系统对比而非消融，只能看方向。
  8. 语料里唯一显式处理跨相机差异的 re-ID 方法论文（#34）不可作为参照：无人工真值、自评估循环、数据不公开、多处物理上不合理的声明。
  9. challenge 排行榜高估了"已解决"的程度。 91–93 的 challenge mAP 靠的是多模型集成、LUPerson 级自监督预训练，以及在 challenge set 上做推理期无监督自适应（#104 的参赛摘要与组织者总结）；单模型、不看测试数据时是 85–87（#103 Table 4：RFES-ReID 86.7、Sports Re-ID 86.0），TransReID-SSL 为 80.1，ImageNet 预训练的 OSNet 76.4。两届之间只涨了 1.6 个 mAP 点，参赛从 13 队降到 5 队。
  10. v3 标注的结构性质已经被参赛者利用，但只用在单帧上。 身份只在 action 内有效，所以同场不同 action 的同一球员是假负样本（#104 MIG 的 A×I×K 采样专门规避）；同一 action 内 gallery 与 query 近似互斥分配（#104 ReBatch 的排名互斥后处理）；同一 action 的图像放进同一 batch 能得到最难的 triplet（#104 ReBatch、#56 CLIP-ReIdent）。这些结构在序列级设定下同样成立。

5.3 可切入的研究点

切入点 1：把 SoccerNet-v3 的单帧跨视角对应升级为序列级基准

  • 问题定义：给定同一动作的直播 tracklet 与回放 tracklet（多路），做 sequence-to-sequence 的跨视角球员匹配；按视角差异分桶报告 mAP / Rank-1。
  • 为什么没被解决：v3 只选了 1 帧（#79）；MVFouls（#47）有同步多视角视频但无身份；SoccerNet-Tracking（#18）有 tracklet 但单视角。三者从未被拼在一起。
  • 可用资源：v3 的 folder 级对应 + 动作时间戳（回原视频需 NDA）；#47 的 3,901 个动作 × 2.29 路裁判对齐视频作为无标注序列源；#84 的 54 场 single-player tracklets + jersey/team 与直播/回放分段统计；#59 的标定；#98 的 tracklet 净化规则（ID count=1、关节置信度 ≥ 0.5）。
  • 预期难点：直播与回放的时间对齐（5 fps 抽帧、≤100 ms 偏移；#53 已观察到解说与回放画面的时间错位会拖垮下游，F1 0.6730 → 0.5291）；回放慢放速度；身份标注要从单帧传播到 tracklet。数据可得性本身未验证：审稿核对指出 v3 的时间元数据含义未界定、能否凭它定位原视频中的 replay 帧原文未说明，SoccerNet-v2 的 13 类机位标签也只覆盖 200 场——12,764 个动作里有多少配了真正不同机位的回放，目前没有任何估计，应先做这一步统计。
  • 第一步实验：先不做方法——用 CLIP-ReIdent 风格的单帧模型 + mean-pooling，在自建的序列版上测"多帧能带来多少"，复现 #31 那条长度曲线的跨视角版本；单帧部分先对齐 #103 Table 4 的 test split 数字（Rank-1 / mAP：Swin-T 基线 75.3 / 80.2、TransReID-SSL 83.8 / 80.1、Sports Re-ID 81.5 / 86.0），确认复现无误再扩到序列；同时设一个强单视角基线（#48 的教训：单视角微调 CLIP 超过了多视角 VARS）。

切入点 2：几何一致性作为跨视角匹配的约束与难负样本来源

  • 问题定义：利用 #59 的 {K,R,t} 把直播帧与回放帧的球员脚点投到同一球场坐标，用位置一致性（及视差不确定性）作为外观相似度的先验或门控。
  • 为什么没被解决：#3 只提出了"用已标定视角三角化球员来辅助标定或身份关联"的设想；GSR 系列（#20/#23/#28）都在单机位内用坐标，没有跨机位。
  • 可用资源：#59 的 4,051 帧标定与 ≥1 m 相机位移筛选；#1/#2/#8 开源标定器；#6/#94/#17 的时序标定（热启动 + 门控重初始化、多帧共享位置、Kalman + 顺序一致性）；#20 的 GS-HOTA（LocSim × IdSim）与 #81 的 mAP-LocSim / Frame Accuracy 可直接推广为共享坐标系下的跨相机身份指标；#104 ReBatch 的"排名互斥"后处理可以升级为 action 内的二分图匹配，代价矩阵由外观距离与球场坐标距离共同构成。
  • 预期难点：非主机位 CR 只有 ~78%（#2/#8）；转播视频上的标定精度远低于静态帧（sn-gamestate 序列 JaC5：TVCalib 19.88、NBJW 37.14、BroadTrack 56.88、#28 69.38）；脚点取法的影响比标定器还大（#81：姿态回归地面点 79.3 vs bbox 底边中点 52.4）；#3 指出 homography 与富模型位置可差 > 1 m；同队球员在坐标上也可能重叠。
  • 第一步实验：在 v3 folder 内，用"同一时刻、球场坐标距离 < d"做候选剪枝，看 CLIP-ReIdent 基线的 Rank-1 提升多少；再用坐标近但身份不同的样本做难负样本挖掘。

切入点 3：视角不变的部件表征——从"处理缺失"到"对齐差异"

  • 问题定义：在 PRTreID（#30）的部位 embedding 之上，加入视角条件化的对齐损失，使同一部位在直播远景与回放近景下的 embedding 一致。
  • 为什么没被解决：#30 的 Eq. 3 只对双方可见部位求平均，没有跨视角不变约束；作者放弃了 v3 的跨相机数据。
  • 可用资源：PRTreID 开源；#31 的 MSRL 可改写为 (D_same-view − D_cross-view)² 的 view-shared refinement loss；#52 的 CropDrop（整段序列掩码外观、强制依赖轨迹与上下文）作为外观不可靠时的正则化；#34 的 viewpoint-entropy 分层评估思路；#1 的机位类型标注可用来构造视角分桶。
  • 预期难点：v3 folder 内身份数极少，triplet 采样需要"同人跨视角正样本 + 同队同视角负样本"（把 #30 的 batch sampler 改写；#104 的 MIG 队已指出同一球员在不同 action 里 ID 不同，同场比赛的多个 action 进同一 batch 会产生假负样本，采样器要么跨大量 action 随机取，要么只在 action 内构造负样本）；MSRL 的原始设定里 RGB/IR 配对帧并不同步而 v3 的 live/replay 近似同步，迁移时需单独论证（审稿核对）；PRTreID Eq. 7 的可见性并集在长序列里会保留陈旧的部位特征。
  • 第一步实验：先复现 #30 在自建集上的 72.59 mAP，再在 v3 folder 配对上零样本测一次，量化"视角代价"；然后加视角对齐损失。

切入点 4：语义属性 + 外观 + 时序的分层关联，在跨视角下重做

  • 问题定义：把 #23/#28/#95 的"号码/球队先拆分再合并、ReID 只做必要条件、时间/阵容硬约束"这套逻辑搬到直播↔回放的 tracklet 关联，并用 #35 的不确定性输出决定何时相信号码。
  • 为什么没被解决：这套逻辑只在单机位 GSR 与单相机 LTPI 上验证过；#95 已经证明硬级联会伤害性能，但没在跨视角下试过 late fusion。
  • 可用资源：#28 微调 1 epoch 的 VLM 属性提取器（或 CLIP+分类头，两者只差 1.35 GS-HOTA）、#35 的 Dirichlet 不确定性、#32 的公开 STR 流水线、#95 的 CSIS/Coverage/MisID 协议、#24 的"不用外观、只按时间重叠合并"对照（去掉后 −4.83 TI-HOTA）。
  • 预期难点：回放近景号码可读、直播远景不可读，两侧的线索强度不对称；同帧同号需用 team 区分（#79 的身份键设计）。
  • 第一步实验：在 v3 folder 上比较三种融合：号码硬门控 / 外观加权 / 不确定性加权 late fusion。

切入点 5：长时程 + 跨视角的评测协议

  • 问题定义：设计一个既有时间漂移又有视角切换的评测，指标带弃权代价（CSIS）并按视角差与时间距离分桶。
  • 为什么没被解决：#95 的协议只有时间维；#56 的 v3 ReID 只有视角维；#34 的 VDRS/TCP 有想法但数据不可信。
  • 可用资源：#95 的时间顺序划分（上半场调参、下半场测试）、#40 的 train-on-one / test-on-all 相机类型矩阵、#67 的 image-level / tracklet-level / open-world 三级设置、#57 的"只在困难实例上评估"思路、#34 的 viewpoint entropy。
  • 第一步实验：把 LTPI 协议套到 SoccerNet-Tracking 的整段 45 分钟半场（#18 挑战集）+ v3 的回放对应上，先做出一个 leaderboard 空位。

切入点 6：无监督/弱监督的跨视角自适应

  • 问题定义：不用 v3 的身份标注，只用"同一时刻多视角 + 场地坐标 + 球衣号伪标签"生成跨视角正样本，做对比学习或聚类微调。
  • 为什么没被解决：#34 的"只允许跨相机建边"是这个方向唯一的尝试，但没有几何门控且评估不可信；#35 的不确定性伪标注只用于号码；#19 的 doubt 加权自训练只用于检测。
  • 可用资源：#59 标定；#35 三档伪标注策略；#19 双阈值 doubt 加权；#95 显示每身份 60 s 就够；#104 TrackMerger 的"同一轨迹取正样本、同时段其它轨迹取负样本"triplet 自监督，以及 #104 re-ID 前列方案在目标集上的推理期无监督自适应。
  • 第一步实验：用"同时刻 + 坐标近 + 号码一致"生成伪正样本，InfoNCE 微调 CLIP，与有监督 CLIP-ReIdent 比较。

5.4 语料的盲区

这批文献以足球转播为主，以下跨视角 re-ID 的关键问题在这里根本没出现：

  • 带真值身份的同步多相机 RGB 序列数据：v3 有对应无序列，Tracking 有序列无多视角，MVFouls 有多视角视频无身份，SGA-INTERACT 有多视角有身份但无 RGB，DeepSport 有多相机有标定无跨相机 ID。
  • 光照/夜间/室内外域偏移：只有 #33（日/夜）和 #34（光照分层）触及，且都是非足球场景。
  • 非球类/非号码衣着的行人：球衣号这一线索在通用 re-ID 中不存在，语料里的成功经验有一部分不可迁移。
  • 在线/实时性：#20 基线 1.1 FPS，#28 依赖 LLaMA-3.2-Vision，#8 2.3 fps；跨视角 + 序列的在线系统无人讨论。
  • 评测的候选池规模：v3 的 folder 内检索候选极少，与开放世界 re-ID 的难度不在一个量级。

5.6 尚未回答的问题

完整性审查列出了五个"准备做这个方向的人一定会追问、但语料回答不了"的问题。它们本身就是开题前要先做的调研：

  1. v3 ReID 的评测协议到底是什么？（补充文献后部分已答） 已知：数据分 train / valid / test / challenge 四份，排行榜按 challenge set 的 mAP 排名，官方 baseline 在 github.com/SoccerNet/sn-reid（#104）；身份标签只在 action 内有效，评测时每个 query 只与同一 action 的 gallery 比较；train 248,234 个样本，test 为 query 11,777 / gallery 34,989（#103 转述 challenge 网站）。按 #79 的 12,764 个 action 与 340,993 张缩略图粗算，平均每个 action 约 27 张缩略图，再按 test 的 query : gallery ≈ 1 : 3 折算，每个 query 面对的候选只有 20 张左右（我的估算，非官方数字）——这解释了为什么 mAP 能到 85–93。仍未回答：query 是否只取直播帧、gallery 是否只取回放帧（即协议是否天然跨视角；按我对 sn-reid 仓库的印象是这样，语料外，需自行核实）、每个 action 的身份数、mAP 怎样跨 action 汇总。需要读 sn-reid 的代码与说明。
  2. 切入点 1 的数据真的可得吗？ 回原视频需 NDA；原文未说明能否凭元数据定位 replay 帧在原视频中的位置；回放慢放倍率未知；13 类机位标签只覆盖 200 场。12,764 个动作里有多少配了真正不同机位的回放，没有任何估计。
  3. 哪些数字在同一 split 上？ GSR 的 test/challenge 与届别（22.26 / 23.36 / 61.48 / 63.81 / 64.1 / 61.5）、号码识别的 test/challenge 命名互换（#56 与 #80/#32/#35 相反）。做 leaderboard 前需要一张对照表。
  4. 现有模型零样本跨视角到底几分？ 有监督单模型的量级现在有了（#103 Table 4，Rank-1 / mAP：OSNet 69.2 / 76.4、TransReID-SSL 83.8 / 80.1、Sports Re-ID 81.5 / 86.0、RFES-ReID 84.1 / 86.7；ResNet50 一行 48.4 / 59.1 疑为 challenge 集官方 baseline 的数字），但零样本模型（PRTreID、不微调的 CLIP）和纯几何（球场坐标）在 v3 folder 上的跨视角 Rank-1 仍然一个数都没有，按视角差分桶的数字也没有；第一版综述给出的代理（同视角 0.98 vs 跨视角 0.93）经审查不成立，已删除。切入点 2/3 的"第一步"都以此为起点，却没有先验量级。
  5. 今天能跑起来的是什么？ 已核实可用：#95（数据、代码、权重）、#20（TrackLab 基线）。已知公开：v3 ReID 的官方 baseline sn-reid（#104）。未核实或有条件：#103 的代码需向作者索取；#30 的开源来自论文外信息；#56 的 CLIP-ReIdent 只有摘要级描述；#23 无代码且数据内部自建；#28 依赖 LLaMA-3.2-Vision 微调；#35 最佳结果依赖私有数据。PRTreID 在 SoccerNet-Tracking 上的权重是否公开、CLIP-ReIdent 是否有实现，材料没答。
